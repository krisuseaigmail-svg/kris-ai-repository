# 机房/办公资产录入台账部署说明

本文说明如何把发布包安装到 Linux 服务器，以及以后如何升级。打包、架构和数据保留的硬性标准见《发布构建标准》。业务行为见《功能说明》。

目标系统是已安装 Docker 的 SUSE Linux Enterprise Server 15.6（x86_64）。程序和数据库都在 Docker 里。宿主机不安装 Python，不需要访问 `registry-1.docker.io`，也不使用宿主机上已经安装的 PostgreSQL。

## 现场红线

下面几条由现场遵守。本产品不会把「后装客户交付台账」自动变成失败。

- 禁止与客户交付台账安装在同一 Docker 宿主机。
- 本产品先安装之后，禁止再在这台机器上安装客户交付台账。对方的安装脚本不会拒绝卷名 `delivery_ledger_pgdata`，后装会挂上这个卷。
- 禁止在运行机直接 `docker compose up`。只允许 `deploy/install.sh`、`deploy/upgrade.sh`、`deploy/up.sh`。
- 禁止 `docker compose down -v`，禁止改卷名，禁止改卷的 compose 项目标签，禁止删除 `asset_ledger.owner`。
- 本版没有登录。只在可信内网放行 `APP_PORT`（默认 `8010`）。能打开该端口的人可以修改和删除台账。
- 删除空间或资产后不能从页面恢复。删除前执行 `deploy/backup.sh`。

## 发布包里有什么

压缩包解开后是目录 `asset-ledger/`，其中有 `app/`、`pyproject.toml`、`deploy/`（含 `lib.sh` 与 `pg-guard.sh`）、`images/`、`功能说明.md`、`发布构建标准.md` 和本文。

数据库文件在 Docker 卷 `delivery_ledger_pgdata`。该卷由本产品独占。账号和密钥在安装目录的 `.env`。这两处都不随程序替换而删除。本版没有上传附件目录。

`.env` 的键与《功能说明》第 2.4 节相同：`DATABASE_URL` 的主机名是 `postgres`，库名和账号名是 `asset_ledger`，`PRODUCT_CODE` 是 `asset-ledger`，`APP_PORT` 默认 `8010`，`TZ` 是 `Asia/Shanghai`。compose 不把 PostgreSQL 的 5432 映射出来。

## 服务器准备

确认下面命令能执行（无需外网拉镜像）：

```bash
docker info
docker compose version
```

必须是 Docker Compose V2 插件（`docker compose`，中间有空格）。不要用单独的 `docker-compose` 可执行文件代替。执行安装脚本的用户要能访问 Docker。需要从其它机器打开页面时，在防火墙上放行 `APP_PORT`。

若本机已经有客户交付台账的容器，或已经有不属于本产品的卷 `delivery_ledger_pgdata`，安装会失败并留下对方的数据。不要为了装本产品去删那只卷。

## 首次安装

把 `asset-ledger-<版本>.tar.gz` 拷到服务器后：

```bash
tar -xzf asset-ledger-0.1.0.tar.gz -C /tmp
sudo /tmp/asset-ledger/deploy/install.sh /opt/asset-ledger
```

安装目录不要用解压出来的 `/tmp/asset-ledger` 本身。脚本会：

1. 发现目标目录已有 `VERSION` 时退出，提示「已有安装，请使用 upgrade.sh」。
2. 调用 `assert_volume_exclusive`（见《功能说明》第 2.1 节）。`COMPOSE_PROJECT_NAME` 若被设成别的值，脚本退出，提示「COMPOSE_PROJECT_NAME 必须是 asset-ledger」。
3. 复制程序，生成 `.env`，权限 `600`。数据库密码是随机值。
4. `docker load` 加载离线镜像，不访问 Docker Hub。
5. `docker compose -p asset-ledger up -d --pull never`。postgres 的 `command` 是 `["postgres"]`，经 `pg-guard.sh` 启动，并在数据目录写入 `asset_ledger.owner`。不写这条 command 时包装进程没有参数，数据库不会起来。

完成后用浏览器打开 `http://<服务器地址>:8010/`。端口以 `.env` 的 `APP_PORT` 为准。

以后在安装目录里启动：

```bash
cd /opt/asset-ledger
./deploy/up.sh
```

`up.sh` 与安装使用同一套预检。查看日志和停止：

```bash
docker compose -p asset-ledger logs -f app
docker compose -p asset-ledger stop
```

停止不要加 `-v`。

## 升级

下一版仍然是带 `images/` 的 `asset-ledger-<新版本>.tar.gz`。升级只替换程序和镜像，并在替换前自动备份。

```bash
tar -xzf asset-ledger-0.1.0.tar.gz -C /tmp
sudo /tmp/asset-ledger/deploy/upgrade.sh /opt/asset-ledger
```

脚本依次：

1. 检查新版本号。比已安装版本更低时停止。确需回退时，先按下一节恢复那一版的备份，再用 `ALLOW_DOWNGRADE=1` 执行升级脚本。
2. 做与安装相同的卷预检。预检失败则不替换、不启动。
3. 把当前数据库备份到 `/opt/asset-ledger/backups/<时间>/`，其中有 `db.sql` 和 `VERSION`。
4. 替换程序和镜像。`.env`、`backups/` 和卷保留。`asset_ledger.owner` 保留。
5. 加载新镜像并启动。`/healthz` 返回 `ok` 才算升级完成。

升级失败时，脚本会打印备份目录。不要删卷。修复后再次执行新包的 `upgrade.sh`。

不要改安装目录的名字，也不要改卷名 `delivery_ledger_pgdata`。卷名一旦变化，新容器会连到一个空数据库。

## 备份与恢复

随时可以单独备份：

```bash
/opt/asset-ledger/deploy/backup.sh /opt/asset-ledger
```

备份时本产品的 postgres 必须已经健康。备份不包含附件包。恢复：

```bash
/opt/asset-ledger/deploy/restore.sh /opt/asset-ledger /opt/asset-ledger/backups/20261111180000
```

恢复只重建数据库 `asset_ledger`：断开该库会话，删除并重建这个库，再灌入 `db.sql`。属主仍是 `asset_ledger`。不删除 `asset_ledger.owner`，不删除其它备份，不执行 `down -v`，也不动客户交付台账的容器。若集群里出现库 `ledger` 或表 `deliveries`，恢复中止，不删除任何库。

## 就绪

应用就绪的判据是 `http://127.0.0.1:8010/healthz` 返回正文 `ok`。端口以 `.env` 的 `APP_PORT` 为准。

预检或启动包装拒绝时，日志里是这些原句之一：「禁止与客户交付台账同机部署」「卷 delivery_ledger_pgdata 不属于本产品，拒绝挂载」「COMPOSE_PROJECT_NAME 必须是 asset-ledger」。应用拒绝建表时，日志里是「PRODUCT_CODE 必须是 asset-ledger」「无法检查数据库卷归属」或「数据库卷与客户交付台账冲突」。用 `docker compose -p asset-ledger logs` 查看，不要只看容器是否在重启。
