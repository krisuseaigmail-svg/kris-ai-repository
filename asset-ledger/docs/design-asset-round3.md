## 1. 本轮补上的门禁

卷名仍是 `delivery_ledger_pgdata`。不改成 `asset_ledger_pgdata`。同机互斥分成三层，缺一不可：

| 层 | 做什么 | 挡什么 |
| --- | --- | --- |
| `deploy/lib.sh` 的 `assert_volume_exclusive` | `install.sh`、`upgrade.sh`、`up.sh` 在任何 `compose up` 之前调用这一个函数。`docker ps -aq` 含已退出容器。始终 `docker compose -p asset-ledger` | 对方容器还在、卷标签不是 `asset-ledger`、`COMPOSE_PROJECT_NAME` 被改掉 |
| `deploy/pg-guard.sh` | compose 里 postgres 的 entrypoint。已初始化的数据目录没有 `asset_ledger.owner`，或内容不是 `asset-ledger`，则退出，不调用官方入口 | 直接 up、标签被改、对方卸容器后留下的 PGDATA。拒开库，不改目录里已有文件 |
| 应用建表前 | 连维护库列出库名，再**逐个 CONNECT** 查 `to_regclass('public.deliveries')` | `PRODUCT_CODE` 或 `DATABASE_URL` 配错，以及有人手工补了标记文件 |

只改 Docker 卷标签、不写 `asset_ledger.owner`，postgres 仍拒绝启动。只写了标记文件、卷标签却是别人的，脚本拒绝 up。`PRODUCT_CODE` 不负责挡卷。

做不到、也不再写成验收的事：本产品先装之后，客户交付台账再安装时对方自动失败。对方脚本不会拒绝这个卷名。这是部署红线，不是技术互锁。

## 3. 终裁（本轮不再打开）

**空间。** 根上是机房、仓库、办公区。机房下面只有机柜。仓库下面只有柜子。办公区下面可以是办公区、柜子、工位。层数含自身最多 4。移动时该节点和全部子孙都要 ≤ 4。机房里的备件放仓库，不在机房下建柜子。

**挂载。** 服务器、交换机、防火墙放在机柜的连续整宽 U，或仓库节点，或根为仓库的柜子（不占 U）。硬盘挂在服务器上，或放在仓库、柜子、办公区、工位。一条资产要么挂空间，要么挂父资产，不能两个都填。不是机柜却带了 U，提示「这里不使用 U 位」。

**卷。** 名字固定 `delivery_ledger_pgdata`。镜像 `asset-ledger`，项目名 `asset-ledger`，库名 `asset_ledger`。禁止与客户交付台账同机并用。postgres 不映射宿主机端口。

不再讨论：改卷名、改客户交付台账的安装脚本、登录、Excel 导入、第二块 MAC、柜子改回只放硬盘、层数放宽到 5。
