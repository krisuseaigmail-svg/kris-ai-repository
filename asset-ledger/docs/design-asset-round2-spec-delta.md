# 第一部分　功能说明

## 1. 目标

资产台账记录机房和办公场所中的服务器、交换机、防火墙和硬盘，供可信内网里的内部人员在线录入，并导出 Excel。

一台资产有资产编号、序列号和位置。服务器、交换机、防火墙放在机柜的 U 位上，或放在仓库里（含仓库下的柜子）。硬盘放在某台服务器里，或放在仓库、柜子、办公区、工位。

应用放在独立目录 `asset-ledger/`。客户交付台账仍在 `delivery-ledger/`。两套产品不共用代码，不互相写入业务数据。

## 2. 技术约束

- 目录是 `asset-ledger/`。依赖写在 `asset-ledger/pyproject.toml`。
- Python 3.12、FastAPI、Jinja2、SQLAlchemy、PostgreSQL 16。应用在容器内用 uvicorn 监听 `8000`。基础镜像是 `python:3.12-slim`。
- 界面语言为简体中文。页面由服务端渲染。表单中文按 UTF-8 还原：应用启动时修正把 `application/x-www-form-urlencoded` 里的 UTF-8 误按 Latin-1 解开的情况；已经是正常 Unicode 的值保持不变。
- 部署在可信内网。本版页面没有登录。
- 宿主机是 SUSE Linux Enterprise Server 15.6（x86_64），已经安装 Docker。宿主机不安装 Python，也不使用宿主机上已有的 PostgreSQL。
- 用 `asset-ledger/docker-compose.yml` 启动 `app` 和 `postgres`。文件中的项目名是 `asset-ledger`。`postgres` 的镜像标签是 `postgres:16`。两个服务的 `pull_policy` 都是 `never`。`postgres` 不写 `ports`，不把 5432 映射到宿主机。
- 数据库连接从 `DATABASE_URL` 读取。主机名是 `postgres`。库名是 `asset_ledger`。账号名是 `asset_ledger`。安装时生成随机密码，`.env` 权限 `600`，库名和账号名保持这两个字。`PRODUCT_CODE` 为 `asset-ledger`。
- compose 卷的 `name` 固定为 `delivery_ledger_pgdata`。本产品独占该卷。禁止与客户交付台账在同一 Docker 宿主机上挂载它。升级、备份和恢复都不更换这个名字，也不执行会删除该卷的命令。挂载前的归属检查见第 2.1 节。
- 默认把容器的 `8000` 映射到宿主机 `8010`，由 `APP_PORT` 覆盖。两个服务的时区都是 `Asia/Shanghai`。
- 本版没有上传文件，compose 不挂附件目录。
- 支持的启动路径是 `deploy/install.sh`、`deploy/upgrade.sh`、`deploy/up.sh`。三条脚本先做第 2.1 节的检查，通过后才 `compose up`。
- `app` 启动时先做第 2.2 节的检查，再创建还不存在的本产品表。已有库按 `app/migrate.py` 里尚未执行的版本补结构。
- 结构版本记在 `schema_migration`。`migrate.py` 只在列表末尾追加。已经执行过的版本不再执行。语句只新增表、新增列，或做不删除用户数据的兼容变更。当前记录：
  - `0.1.0`：初始表 `spaces`、`assets`，由启动时创建。
- 根空间的同名使用 `parent_id IS NULL` 的部分唯一索引；非根使用 `(parent_id, lower(name))` 的部分唯一索引。资产编号、序列号各自有 `lower(...)` 的唯一索引。
- 父级、放置空间、挂载资产是外键，数据库侧为 RESTRICT。完整性错误按第 4.3 节和第 6 节译成中文，HTTP 状态不是 500。
- Excel 使用 `openpyxl==3.1.5` 与 `et-xmlfile==2.0.0`。运行依赖随离线镜像发布。运行机不执行 pip。
- 校验失败时 HTTP 400，页面含规定的那一句提示，数据库不变。创建或修改成功时 303 到该条详情。对象不存在时 HTTP 404。
- 用 pytest 覆盖第 9 节。测试连接 PostgreSQL。连接串的库名是 `asset_ledger_test`，不得使用安装目录 `.env` 里的现场库，也不得把测试指到卷 `delivery_ledger_pgdata` 上的业务库。

运行依赖版本：`fastapi==0.115.6`、`uvicorn==0.32.1`、`jinja2==3.1.4`、`sqlalchemy==2.0.36`、`psycopg[binary]>=3.2.4`、`python-multipart==0.0.17`、`itsdangerous==2.2.0`、`openpyxl==3.1.5`、`et-xmlfile==2.0.0`。

### 2.1 挂载卷之前

`install.sh`、`upgrade.sh`、`up.sh` 在 `compose up` 之前按顺序检查。任一步失败则向 stderr 输出对应句子，退出码非 0，不执行 up，不执行 `docker volume rm`，不执行 `docker compose down -v`，不停止、不删除客户交付台账的容器。

1. 下面任一成立时，输出「禁止与客户交付台账同机部署」：
   - 存在容器，其镜像去掉标签后的最后一段仓库名是 `delivery-ledger`；
   - 存在容器，标签 `com.docker.compose.project` 是 `delivery-ledger`；
   - 存在容器，挂载了名为 `delivery_ledger_pgdata` 的卷，且其 `com.docker.compose.project` 不是 `asset-ledger`。
2. 卷 `delivery_ledger_pgdata` 已存在，且标签 `com.docker.compose.project` 不是 `asset-ledger`（含没有该标签）：输出「卷 delivery_ledger_pgdata 不属于本产品，拒绝挂载」。
3. 卷不存在，或该标签已经是 `asset-ledger`：才允许 up。compose 文件含 `name: asset-ledger`。本产品因此创建的卷带上项目标签 `asset-ledger`。已由本产品创建的卷在升级时通过第 2 步。

只把 `delivery-ledger` 镜像 load 进本机、还没有对应容器、卷也还不存在时，第 1 步不拒绝。部署说明禁止在这之后再安装客户交付台账。

### 2.2 建表之前

应用在创建 `spaces`、`assets` 和写入 `schema_migration` 之前完成下面三步。失败则进程退出码非 0，不建这些表，不写 `schema_migration`。

1. 环境变量 `PRODUCT_CODE` 恰好是 `asset-ledger`。否则日志含「PRODUCT_CODE 必须是 asset-ledger」。
2. 用与业务库相同的账号和密码连接维护库 `postgres`，而不是只连接 `asset_ledger`。查询 `pg_database` 中全部非模板库。存在名为 `ledger` 的数据库，或任一非模板库中 `public.deliveries` 是表：日志含「数据库卷与客户交付台账冲突」。
3. 连不上维护库：日志含「无法检查数据库卷归属」。

只查询当前库 `asset_ledger` 有没有 `deliveries`，不能当作第 2 步通过。本产品自己的表名不使用 `deliveries`，库名不使用 `ledger`。其它表名不触发第 2 步。

`/healthz` 在业务库可连接且第 2.2 节已通过时返回 200，响应体去掉首尾空白后是 `ok`。检查未通过时进程不提供该响应。

## 3. 对象关系

```text
空间（机房 / 机柜 / 仓库 / 办公区 / 柜子 / 工位）
  └── 子空间（按第 4 节矩阵）
资产
  ├── 放在一个空间上（服务器、交换机、防火墙、硬盘）
  └── 或挂在一台服务器上（仅硬盘）
```

每条资产恰好有一个宿主：要么有空间外键，要么有挂载资产外键。硬盘挂在服务器上时不记空间外键。它的空间路径等于那台服务器当前的空间路径。

## 4. 空间

| 内部码 | 页面用词 |
| --- | --- |
| `room` | 机房 |
| `rack` | 机柜 |
| `warehouse` | 仓库 |
| `office` | 办公区 |
| `cabinet` | 柜子 |
| `desk` | 工位 |

### 4.1 父子关系

行是子类型，列是父级。空父级是根。「可」表示允许创建和移入，其余组合拒绝。

| 子类型 | 根 | 机房 | 机柜 | 仓库 | 办公区 | 柜子 | 工位 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 机房 | 可 |  |  |  |  |  |  |
| 机柜 |  | 可 |  |  |  |  |  |
| 仓库 | 可 |  |  |  |  |  |  |
| 办公区 | 可 |  |  |  | 可 |  |  |
| 柜子 |  |  |  | 可 | 可 |  |  |
| 工位 |  |  |  |  | 可 |  |  |

机房的子空间只有机柜。机房内的备件放在仓库节点，或放在仓库下的柜子。在机房下创建柜子时提示「这里不能放柜子」，不产生记录。

拒绝提示用子类型的页面用词：

- 「这里不能放机房」
- 「这里不能放机柜」
- 「这里不能放仓库」
- 「这里不能放办公区」
- 「这里不能放柜子」
- 「这里不能放工位」

类型取值不属于上表时提示「类型无效」。

名称必填。去掉首尾空白后长度为 1–100，且不含 `/` 或 `\`。同一父级下，名称忽略大小写后唯一，重复时提示「同级已有这个名称」。不同父级可以同名。根与根也按同级比较。说明可空，最长 2000。

提示：名称为空「请填写名称」；名称过长「名称过长」；含 `/` 或 `\`「名称不能含斜杠」；说明过长「说明过长」。

编辑时表单可以再次提交类型。提交类型与库中类型相同，则继续保存名称、父级、说明和机柜高度。提交类型与库中类型不同，提示「类型创建后不能改」，类型、父级和名称都保持原值。

### 4.2 层数

层数从根算到该节点，包含自身，最多 4。

创建时，新节点层数是父节点层数加 1；父级为空则新节点层数是 1。超过 4 则提示「空间层级过深」，不产生节点。

移动时，该节点的新层数，以及它每一个子孙的新层数，都要小于或等于 4。子孙的新层数等于该节点的新层数，加上子孙相对该节点的距离。有任一节点会超过 4，则提示「空间层级过深」，父级保持移动前的值，子孙关系不变。

因此路径「办公区 / 办公区 / 办公区 / 工位」可以保存。连续四层办公区可以保存。把「办公A / 办公B / 办公C / 工位D」整棵移到另一间根办公区下面时，工位会变成第 5 层，整次拒绝。

父级必须存在。父级编号没有对应空间时提示「位置不存在」，父级不变。新父级是自己，或是自己的子孙时，提示「不能放到自己的下级」，父级不变。把子树移到自己的祖先下面，只要矩阵和层数都允许，就保存。

移动成功之前，还要检查该空间及子孙上已有资产在新位置下仍满足第 5 节。不满足则提示「移动后已有资产不能留在这里」，父级不变。把放着服务器的仓库柜子移到办公区下，属于这一句。

### 4.3 机柜高度、删除

只有机柜有高度，取值是 1 到 52 的整数，含两端。新建表单预填 42，保存以提交值为准。缺高度时提示「请填写机柜高度」。超出范围、不是整数时提示「机柜高度无效」。其它类型的高度必须为空。提交了高度时提示「这里不使用机柜高度」，不写入。

把机柜高度改到小于本机柜已有设备最高占用 U 时拒绝，提示「机柜高度小于已占用 U 位」，高度保持原值。已有设备的最高 U 在缩小之前按第 5.2 节的闭区间计算。

删除须带确认值 `yes`。不是 `yes` 时提示「请确认删除」，空间还在。存在子空间时提示「下面还有空间」。存在直接放在本空间上的资产时提示「这里还有资产」。挂在服务器上的硬盘不是机柜的直接资产；机柜上还有那台服务器时，删除机柜仍提示「这里还有资产」。

数据库 RESTRICT 触发时，按仍存在的子空间、直接资产返回上面两句，HTTP 400，不返回 500。

### 4.4 空间保存时的提示顺序

一次保存只返回第一句：

1. 名称、说明的必填、长度和斜杠。
2. 编辑时类型与库中不同：「类型创建后不能改」。
3. 机柜的高度格式；非机柜却带了高度。
4. 父子矩阵。
5. 父级是自己或子孙。
6. 该节点及全部子孙的新层数。
7. 移动后已有资产是否仍能留在新位置。
8. 同级名称唯一。

把机房的父级设成它下面的机柜时，第 4 步先返回「这里不能放机房」。把办公区的父级设成自己时，矩阵允许办公区挂在办公区下，第 5 步返回「不能放到自己的下级」。

## 5. 资产与位置

| 内部码 | 页面用词 |
| --- | --- |
| `server` | 服务器 |
| `switch` | 交换机 |
| `firewall` | 防火墙 |
| `disk` | 硬盘 |

类型取值不属于上表时提示「类型无效」。

### 5.1 宿主

空间外键与挂载资产外键恰好一个有值。

- 两个都有值：提示「请只选择一种位置」，不写库。
- 两个都为空：提示「请选择位置」。
- 所指数编号不存在：提示「位置不存在」。

只有硬盘可以把挂载资产外键指向一台服务器。目标不是服务器时提示「挂载目标不是服务器」。

允许的组合：

| 资产 | 机柜，占连续 U | 仓库节点 | 柜子，且根空间是仓库 | 柜子，且根空间是办公区 | 办公区 | 工位 | 服务器 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 服务器 | 可 | 可 | 可 |  |  |  |  |
| 交换机 | 可 | 可 | 可 |  |  |  |  |
| 防火墙 | 可 | 可 | 可 |  |  |  |  |
| 硬盘 |  | 可 | 可 | 可 | 可 | 可 | 可 |

根空间是沿父级向上、父级为空的那个空间。机房节点不能直接放置资产。仓库下的柜子可以放置服务器、交换机、防火墙和硬盘，不使用 U。办公区下的柜子只放置硬盘。

不允许的组合提示「服务器不能放在这里」「交换机不能放在这里」「防火墙不能放在这里」或「硬盘不能放在这里」。硬盘放在机房节点上时用「硬盘不能放在这里」。

还没有任何一种合法空间可供当前类型选择时，表单提示「请先创建可以放置这种设备的空间」。

本资产上仍挂着硬盘，且新类型不是服务器：提示「请先移出硬盘」，类型和宿主都不变。硬盘改成服务器、交换机或防火墙时，若挂载资产外键仍有值，按新类型提示「服务器不能放在这里」「交换机不能放在这里」或「防火墙不能放在这里」，类型和宿主都不变。

### 5.2 U 位

U 位只用于放在机柜上的服务器、交换机和防火墙。

宿主不是机柜时，起始 U 或占用高度只要有一个提交了非空值，就提示「这里不使用 U 位」，不计算这段区间是否超出机柜。只提交占用高度、不提交起始 U，也是这一句。

宿主是机柜时：

- 起始 U 为空：提示「请填写起始 U」。
- 占用高度为空：提示「请填写占用高度」。
- 起始 U 不是整数：提示「起始 U 无效」。
- 占用高度不是大于或等于 1 的整数（含 0、负数、小数）：提示「占用高度无效」。
- 起始 U 与占用高度都是合法整数，但闭区间没有整个落在 1 到该机柜高度之间（含起始 U 为 0）：提示「U 位超出机柜」。
- 闭区间与同一机柜上另一条资产的闭区间相交（含只在端点相接）：提示「U 位重叠」，已有资产的 U 不变。

闭区间是从起始 U 到「起始 U + 占用高度 - 1」，两端都占用。`[1,2]` 与 `[3,4]` 不相交，可以同时保存。`[1,2]` 与 `[2,2]` 相交，拒绝后一条。

新建表单预填占用高度：服务器为 2，交换机和防火墙为 1。该值随表单提交则写入。提交值为空时按上一列提示拒绝。服务端收到空值时，不改写成 2 或 1。

检查重叠的事务按这个顺序做完再提交：锁定该机柜的空间行（`FOR UPDATE`），锁定该机柜上已有资产行，排除正在保存的这一条自身，判断相交，然后写入。两个并发请求写入同一机柜的同一 U 时，只有一条成功，另一条提示「U 位重叠」。

本版按机柜正面的整宽 U 记录。同一 U 上只放一条资产。

### 5.3 硬盘与服务器

硬盘的 BMC IP、业务 IP 和 MAC 保存为空。页面在这三项上对硬盘不作为可填的网络身份；若提交了非空值，按第 6 节拒绝。

硬盘挂在服务器上时，位置备注可写槽位。槽位不参与唯一性，两块硬盘可以写同一个槽位。

删除仍挂有硬盘的服务器时提示「请先移出硬盘」，服务器和硬盘都还在。先把这些硬盘改挂到仓库或其它允许的空间，再删除服务器，则服务器删除成功，硬盘留在新位置。删除硬盘成功时，它所挂的服务器还在。

服务器改到另一个允许的宿主之后，这些硬盘的挂载目标不变。导出中硬盘的空间路径改为服务器的新路径。

数据库 RESTRICT 在删除服务器时若因仍有硬盘而失败，返回「请先移出硬盘」，HTTP 400，不返回 500。

### 5.4 资产保存时的提示顺序

一次保存只返回第一句：

1. 第 6 节的必填、长度和空白。
2. IP、MAC 的格式。
3. 硬盘上的 BMC IP、业务 IP、MAC。
4. 两个宿主外键都有值，或都为空，或目标不存在。
5. 本资产仍挂着硬盘，且新类型不是服务器。
6. 宿主类型是否允许，含挂载目标不是服务器，以及改类型后旧宿主不再合法。
7. 宿主不是机柜却带了 U。
8. 机柜上的 U 格式、区间和重叠。
9. 资产编号、序列号的唯一性。

## 6. 字段与唯一性

| 字段 | 要求 |
| --- | --- |
| 资产编号 | 必填。去掉首尾空白后 1–64 字，中间不能有空白。忽略大小写后在全部资产中唯一 |
| 序列号 | 必填。去掉首尾空白后 1–128 字，中间不能有空白。忽略大小写后在全部资产中唯一 |
| 名称 | 必填。去掉首尾空白后 1–200 字 |
| 类型 | 第 5 节四种之一 |
| 型号 | 可空，最长 200。自由文本，不是型号库 |
| BMC IP | 可空。有值时为点分十进制 IPv4，四段都是 0–255 的十进制整数，不带前导零。硬盘必须为空 |
| 业务 IP | 与 BMC IP 相同。可以与另一条资产相同 |
| MAC | 可空。输入可以是冒号分隔、连字符分隔或 12 位连续十六进制。保存并显示为小写冒号形式，共 17 个字符。硬盘必须为空。可以与另一条资产相同。页面在该字段旁写「本版只记录一块 MAC」 |
| 位置备注 | 可空，最长 200 |
| 备注 | 可空，最长 4000 |
| 登记时间 | 创建时写入，以后修改不改变。时区 `Asia/Shanghai` |

库中保存去掉首尾空白后的原文大小写。唯一索引建在小写形式上。并发冲突与普通重复使用同一提示。资产编号和序列号互不替代：一条的编号可以与另一条的序列号文本相同。

提示：

- 资产编号为空：「请填写资产编号」
- 序列号为空：「请填写序列号」
- 资产名称为空：「请填写名称」
- 资产编号过长：「资产编号过长」
- 序列号过长：「序列号过长」
- 名称过长：「名称过长」
- 型号过长：「型号过长」
- 位置备注过长：「位置备注过长」
- 备注过长：「备注过长」
- 资产编号中间有空白：「资产编号不能有空格」
- 序列号中间有空白：「序列号不能有空格」
- 资产编号重复：「资产编号已存在」
- 序列号重复：「序列号已存在」
- IP 不合法：「IP 格式不正确」
- MAC 不合法：「MAC 格式不正确」

硬盘若填写了网络字段，按 BMC IP、业务 IP、MAC 的顺序只提示第一个：「硬盘不记录 BMC」「硬盘不记录业务 IP」「硬盘不记录 MAC」。

唯一约束冲突时返回上表里的「已存在」句子，HTTP 400，不返回 500。

## 7. 页面

导航是首页、空间、资产。没有登录表单。

首页显示空间数、资产数、硬盘数，以及最近创建的 20 条资产。硬盘数是类型为硬盘的资产条数，包含挂在服务器上的硬盘。每条链到该资产。

空间列表按父子缩进显示全部空间。空库时说明先建立机房、仓库或办公区，工位要建在办公区下。新建根空间时，类型只有机房、仓库、办公区。空间详情显示从根开始的路径、类型、说明、子空间和本范围资产。添加子空间时，类型下拉只含第 4.1 节允许的子类型。机柜详情显示高度，以及从高 U 到 1 的只读占用表；跨 U 的设备在每一行显示同一资产编号和名称。空 U 只显示 U 号。上架在资产表单里保存。

资产列表显示资产编号、序列号、名称、类型、位置、BMC IP、业务 IP、MAC。位置是空间路径；挂在服务器上的硬盘显示「服务器 」加那台服务器的资产编号。筛选有类型、空间和关键字，三者同时生效。关键字忽略大小写，匹配资产编号、序列号、名称和型号。空间筛选包含该空间的子孙，以及挂在这些空间中的服务器上的硬盘。列表每页 200 条。

资产新建和编辑使用同一组字段和同一套校验。保存失败时已提交的内容留在表单中，原记录不变。

空间或资产的页面不存在时返回 404。空间的文案是「没有这个空间」，资产是「没有这个资产」。

路由：

- `GET /` 首页
- `GET /healthz` 见第 2.2 节
- `GET /spaces`、`POST /spaces` 空间列表和创建
- `GET /spaces/{id}`、`POST /spaces/{id}` 空间详情和修改
- `POST /spaces/{id}/delete` 删除空间
- `GET /spaces/{id}/export.xlsx` 导出该空间范围
- `GET /assets`、`GET /assets/new`、`POST /assets` 资产列表、新建表单和创建
- `GET /assets/{id}`、`POST /assets/{id}` 资产详情和修改
- `POST /assets/{id}/delete` 删除资产
- `GET /assets/export.xlsx` 按列表筛选导出

`/assets/new`、`/assets/export.xlsx` 优先于按编号取出资产的路由。

## 8. Excel

资产列表和空间详情可以导出当前范围。页面没有上传 Excel 的入口。

文件只有一个工作表，表名「资产」。第 1 行依次为：

资产编号、序列号、名称、类型、型号、宿主种类、空间路径、起始U、占用U、挂载于资产编号、BMC IP、业务 IP、MAC、位置备注、备注、登记时间。

类型使用第 5 节的页面用词。宿主种类使用：机柜、仓库、柜子、办公区、工位、服务器。

空间路径从根到该空间，名称之间用 ` / ` 连接。硬盘挂在服务器上时，空间路径等于服务器的空间路径，宿主种类为「服务器」，挂载于资产编号为服务器的资产编号，起始 U 与占用高度为空。

起始 U 和占用高度在有值时写成整数，没有时单元格为空。其它空字段也是空单元格。登记时间的格式是 `YYYY-MM-DD HH:MM`，时区是 `Asia/Shanghai`。

行序按资产编号忽略大小写的字典序，再按资产编号原文。

列表导出服从第 7 节的筛选，包含全部命中行，不受 200 条分页限制。没有任何筛选时，下载文件名是 `资产台账.xlsx`。有筛选时文件名是 `资产台账-筛选.xlsx`。

空间详情导出的范围，等于资产列表以该空间为筛选条件的范围。`filename*` 使用「资产台账-」加上空间名称；名称中不能用于文件名的字符替换为下划线。

响应头同时给出 ASCII 兜底名和 UTF-8 名：

```text
Content-Disposition: attachment; filename="asset-ledger.xlsx"; filename*=UTF-8''%E8%B5%84%E4%BA%A7%E5%8F%B0%E8%B4%A6.xlsx
```

有筛选时，`filename` 为 `asset-ledger-filter.xlsx`，`filename*` 是 `资产台账-筛选.xlsx` 的 UTF-8 百分号编码。空间导出的 `filename` 为 `asset-ledger-space.xlsx`，`filename*` 是上一节的中文文件名。

从一间机房导出时，包含这间机房中各机柜上的设备，以及挂在这些设备上的硬盘，不包含只放在其它仓库的硬盘。

## 9. 验收

1. 在根上创建机房、仓库、办公区可以保存。在根上创建机柜、柜子、工位时分别提示「这里不能放机柜」「这里不能放柜子」「这里不能放工位」，数据库里没有这三条。
2. 机房下可以创建机柜。机房下创建柜子时提示「这里不能放柜子」，该机房下没有柜子。机房下创建仓库、办公区、工位或第二间机房时拒绝。机柜、柜子、工位下创建任何空间都拒绝。
3. 仓库下可以创建柜子。仓库下创建机柜、机房、仓库、办公区或工位时拒绝。办公区下可以创建办公区、柜子和工位。
4. 连续三层办公区，最底层下的工位可以保存，层数为 4。连续四层办公区可以保存。层数已经是 4 的办公区下再创建工位时提示「空间层级过深」，节点数不变。层数为 3 的办公区下可以创建柜子；该柜子下再创建空间时提示「这里不能放」加所提交的类型，而不是「空间层级过深」。
5. 同一父级下把名称改成与同级现有名称仅大小写不同的值时，提示「同级已有这个名称」，原名称还在。两个机房下的机柜可以使用同一个名称。名称含 `/` 或 `\` 时提示「名称不能含斜杠」。两个根机房的名称仅大小写不同时拒绝。
6. 编辑空间时再次提交与库中相同的类型，并改名称，名称变为新值。提交另一种类型时提示「类型创建后不能改」，类型和名称都不变。
7. 把机柜的父级改为空时提示「这里不能放机柜」，父级仍是原来的机房。把子办公区的父级改为空，该办公区成为根并保存成功。
8. 把空间的父级设为自己时提示「不能放到自己的下级」，父级不变。把机房的父级设成它下面的机柜时提示「这里不能放机房」，父级不变。
9. 已有「办公A / 办公B / 办公C / 工位D」，另有根办公E。把办公A 的父级改为办公E 时提示「空间层级过深」，办公A 的父级仍为空，工位D 的路径不变。
10. 把仍放着服务器的仓库柜子移到办公区下时提示「移动后已有资产不能留在这里」，父级仍是仓库。给仓库提交机柜高度时提示「这里不使用机柜高度」，仓库的高度仍为空。
11. 删除仍有子空间的空间时提示「下面还有空间」。删除仍有直接资产的空间时提示「这里还有资产」。机柜上有服务器、该服务器上有硬盘时，删除机柜仍提示「这里还有资产」。确认值不是 `yes` 时提示「请确认删除」。这四种情况下原空间还在。直接造成外键拒绝的删除返回上述中文，状态码不是 500。
12. 服务器、交换机、防火墙可以保存在机柜的合法 U 上，可以保存在仓库节点上，也可以保存在根为仓库的柜子里。后一种的起始 U 和占用高度为空，三条都能保存，同一柜子还可以再保存一块硬盘。保存到办公区、工位、根为办公区的柜子或机房节点时拒绝，提示分别为「服务器不能放在这里」「交换机不能放在这里」「防火墙不能放在这里」，不产生资产。
13. 硬盘可以挂到一台服务器上，也可以放在仓库、柜子、办公区、工位。放在机柜上或机房节点上时提示「硬盘不能放在这里」。挂载目标是交换机、防火墙或另一块硬盘时提示「挂载目标不是服务器」。
14. 同一请求里空间外键和挂载资产外键都有值时，提示「请只选择一种位置」，不产生资产，已有行不变。两个都空时提示「请选择位置」。
15. 同一机柜中起始 U 为 1、占用高度为 2 的设备，与起始 U 为 3、占用高度为 2 的设备，都可以保存。把后者改为起始 U 为 2、占用高度为 2 时提示「U 位重叠」，原 U 不变。起始 U 为 2、占用高度为 1 的设备与已占用 `[1,2]` 的设备也不能同时存在。
16. 仓库中的服务器只提交占用高度、不提交起始 U 时，提示「这里不使用 U 位」，页面正文里没有「U 位超出机柜」。
17. 占用高度为 0 或 1.5 时提示「占用高度无效」。机柜上的起始 U 为 0 时提示「U 位超出机柜」。缺起始 U 时提示「请填写起始 U」。缺占用高度时提示「请填写占用高度」。新建服务器不修改预填值直接提交，占用高度保存为 2。
18. 已有设备占用到第 12U 时，把机柜高度改为 10，提示「机柜高度小于已占用 U 位」，高度仍是原值。高度为 0 或 53 时提示「机柜高度无效」。
19. 资产编号为空白时提示「请填写资产编号」。序列号为空白时提示「请填写序列号」。已有编号 `Ab` 时再保存 `ab`，提示「资产编号已存在」。序列号同样忽略大小写。中间含空格时分别提示「资产编号不能有空格」「序列号不能有空格」。名称只含空白时提示「请填写名称」。
20. 业务 IP 为 `192.168.001.1` 或 `bmc` 时提示「IP 格式不正确」。MAC 输入 `AABBCCDDEEFF` 后，页面和导出都是 `aa:bb:cc:dd:ee:ff`。硬盘填写 BMC IP 时提示「硬盘不记录 BMC」，不产生该硬盘。两台服务器保存同一个业务 IP 时两条都在。资产表单的 MAC 字段旁有「本版只记录一块 MAC」。
21. 服务器仍在机柜上时把类型改成硬盘，提示「硬盘不能放在这里」，类型仍是服务器。服务器上还有硬盘时把类型改成交换机，提示「请先移出硬盘」，类型仍是服务器。硬盘仍挂在服务器上时把类型改成服务器，提示「服务器不能放在这里」，类型仍是硬盘。
22. 服务器上还有硬盘时删除服务器，提示「请先移出硬盘」，两条都还在，状态码不是 500。把该硬盘改放到仓库后再删除服务器，服务器消失，硬盘仍在仓库。单独删除硬盘后，服务器还在。把服务器改到另一机柜的空闲 U 后，硬盘的挂载目标仍是它，导出里该硬盘的空间路径是新机柜的路径。
23. 无筛选导出的工作表名为「资产」，第 1 行 16 列与第 8 节一致，文件名为 `资产台账.xlsx`。响应头含 `filename="asset-ledger.xlsx"` 和 `filename*=UTF-8''%E8%B5%84%E4%BA%A7%E5%8F%B0%E8%B4%A6.xlsx`。类型筛选为硬盘时，数据行的类型都是「硬盘」，`filename*` 对应 `资产台账-筛选.xlsx`。从某机房导出时，含该机房机柜内的设备及其硬盘，不含只放在其它仓库的硬盘。
24. 首页、空间页和资产页都没有登录表单。首页硬盘数等于类型为硬盘的条数，含挂在服务器上的。数据库可连接且启动检查已通过时，`GET /healthz` 返回 200，正文去掉空白后是 `ok`。
25. compose 里卷的 `name` 是 `delivery_ledger_pgdata`，项目名是 `asset-ledger`，应用镜像是 `asset-ledger`，库名是 `asset_ledger`。`postgres` 服务没有 `ports`。两个服务都是 `pull_policy: never`。
26. 本机已有镜像仓库名为 `delivery-ledger` 的容器，或卷 `delivery_ledger_pgdata` 的项目标签不是 `asset-ledger` 时，`install.sh` 以非 0 退出，不执行 compose up，不删除该卷。已装客户交付台账时，其库中 `deliveries` 的行数和抽样列值与安装尝试前相同。
27. 干净环境安装成功后，该卷的 `com.docker.compose.project` 是 `asset-ledger`。`PRODUCT_CODE` 不是 `asset-ledger` 时应用退出，不创建 `assets`。维护库 `postgres` 上能看到名为 `ledger` 的数据库，或任一非模板库有 `public.deliveries` 时，日志含「数据库卷与客户交付台账冲突」，不创建 `assets`，不写 `schema_migration`。只在库 `asset_ledger` 里找不到 `deliveries`，不能使这次启动继续建表。
28. 两个并发请求把两台服务器写入同一机柜的同一 U，恰有一条成功，另一条提示「U 位重叠」，该 U 上只有一条资产。

## 10. 后续迭代

以后的版本可以在本节增加能力。增加表或列时，在 `migrate.py` 末尾追加结构版本，已有空间和资产的编号、序列号、名称和位置保持原值。

后续迭代包括：登录和权限；自动发现；端口、网线和光纤；机柜拖拽、背面和半 U；厂商型号库；PDU 监控；Excel 导入；办公终端等新的资产类型；货架或库区；尚未指定位置的资产；报废、维修和借出；变更流水；BMC MAC 与业务 MAC 分列；IPv6；附件。

# 第二部分　发布构建标准

本文固化打包、升级和数据保留。现场步骤见《部署说明》。业务行为见《功能说明》。

## 1. 目标运行环境

| 项 | 标准 |
| --- | --- |
| 操作系统 | SUSE Linux Enterprise Server 15.6 |
| CPU | x86_64。镜像架构名 `linux/amd64` |
| 运行方式 | Docker 与 Compose。宿主机不安装 Python |
| 外网 | 运行机可以没有 DNS，也不能访问 `registry-1.docker.io` |
| 数据库 | 只使用本产品 compose 内的 `postgres:16`。卷名固定 `delivery_ledger_pgdata`。本产品独占该卷。禁止与客户交付台账同机挂载。不映射宿主机 5432，不使用、不改写宿主机已有的 PostgreSQL |

## 2. 离线镜像

### 2.1 发布包

产物路径是 `dist/asset-ledger-<版本>.tar.gz`。包内有：

- `VERSION`，与 `pyproject.toml`、compose 默认 `APP_VERSION` 一致
- `images/asset-ledger-images-amd64.tar.gz`
- `vendor/wheels/` 中的运行依赖 wheel
- `deploy/install.sh`、`deploy/upgrade.sh`、`deploy/up.sh`、`deploy/backup.sh`、`deploy/restore.sh`
- `Dockerfile`、`docker-compose.yml`、`.env.example`
- `功能说明.md`、`部署说明.md`、本文

包内没有现场 `.env`，没有业务库数据，没有 `backups/`。本版没有用户附件目录。

### 2.2 镜像与架构

包内镜像只有：

1. `asset-ledger:<版本>`
2. `postgres:16`

二者都是单架构 `linux/amd64`。`docker image inspect <镜像> --format '{{.Architecture}}'` 为 `amd64`。`docker run --rm --platform linux/amd64 <镜像> uname -m` 为 `x86_64`。

在 Apple Silicon 上，`docker pull --platform linux/amd64` 之后还要压扁：`docker create --platform linux/amd64` 得到容器，再 `docker commit` 成本地标签，然后做上面的两项检查。只 pull、不 commit 的镜像不得打进发布包。禁止把 arm64 内容标成 amd64。

基础镜像的拉取前缀默认是 `docker.m.daocloud.io/library`，可由 `PACKAGE_BASE_MIRROR` 覆盖。打进发布包的标签仍是 `python:3.12-slim` 压扁后的构建结果，以及 `asset-ledger:<版本>` 与 `postgres:16`。应用 Dockerfile 的 `FROM` 是 `python:3.12-slim`。

构建应用镜像使用 `vendor/wheels` 离线安装。Dockerfile 的安装命令只有 `pip install --no-cache-dir --no-index --find-links=/wheels`。目录里没有覆盖依赖的 wheel 时，构建失败，不访问 PyPI。

wheel 的取得：

- 带二进制扩展的包使用 `pip download --python-version 312 --platform manylinux2014_x86_64 --implementation cp --abi cp312 --only-binary=:all:`。
- `openpyxl`、`et-xmlfile` 以及其它 `py3-none-any` 包另一次 `pip download` 放进同一个 `vendor/wheels`，这次不使用会滤掉 `py3-none-any` 的 `--platform`。

compose 中 `app`、`postgres` 都设 `pull_policy: never`。安装和升级只 `docker load`，再 `compose up --pull never`。

### 2.3 打包命令

在能访问镜像站的开发机执行 `./deploy/package.sh`。禁止用未压扁的镜像手工 `docker save` 代替该脚本。

### 2.4 发版前核对

- `VERSION` 已递增。降级必须显式 `ALLOW_DOWNGRADE=1`。
- 包内两镜像的 `Architecture` 都是 `amd64`，且 `uname -m` 是 `x86_64`。
- 包内没有现场 `.env` 和业务数据。
- `migrate.py` 若有变更，只在列表末尾追加。
- compose 的 postgres 没有 `ports`。
- 卷名仍是 `delivery_ledger_pgdata`，项目名是 `asset-ledger`。

## 3. 安装与升级

现场安装使用新包里的：

```bash
sudo /tmp/asset-ledger/deploy/install.sh /opt/asset-ledger
```

目标目录已有 `VERSION` 时，脚本退出，提示「已有安装，请使用 upgrade.sh」，不覆盖该目录。

升级使用：

```bash
sudo /tmp/asset-ledger/deploy/upgrade.sh /opt/asset-ledger
```

升级脚本依次：拒绝静默降级；先备份；替换程序和镜像；保留 `.env`、`backups/` 和卷；加载镜像并启动；`/healthz` 成功才算完成。`install.sh`、`upgrade.sh`、`up.sh` 都先执行《功能说明》第 2.1 节，失败则不 up。

运行机禁止 `docker compose build`、`docker compose pull` 和 `docker compose down -v`。

## 4. 数据保留

业务数据在卷 `delivery_ledger_pgdata`。该卷在同一 Docker 宿主机上只由本产品挂载。客户交付台账不得挂载它。脚本在卷不属于本产品时拒绝挂载，不删除已有卷。

备份目录是安装目录下的 `backups/<时间>/`，至少含 `db.sql` 和当时的 `VERSION`。本版没有附件，备份不要求 `files.tar.gz`。恢复使用这份 `db.sql`，不删除其它备份目录。

结构变更只通过 `app/migrate.py` 末尾追加。禁止用清空库作为升级步骤。pytest 不得使用现场 `.env` 的 `DATABASE_URL`，库名用 `asset_ledger_test`。

升级后至少核对：升级前的空间和资产仍在；`.env` 中的库密码未变；应用仍使用卷 `delivery_ledger_pgdata`，且该卷的 compose 项目标签仍是 `asset-ledger`。

# 第三部分　部署说明硬性条款

目标系统是已安装 Docker 的 SUSE Linux Enterprise Server 15.6（x86_64）。程序和数据库都在 Docker 里。宿主机不安装 Python，不需要访问 `registry-1.docker.io`，也不使用宿主机上已经安装的 PostgreSQL。

压缩包解开后是目录 `asset-ledger/`。数据库文件在 Docker 卷 `delivery_ledger_pgdata`。该卷由本产品独占。禁止与客户交付台账安装在同一 Docker 宿主机上，禁止两套产品挂载这个卷。对方若已经占用该卷，`install.sh` 会失败并留下对方的卷。本产品先安装之后，不要再在这台机器上安装客户交付台账：对方的安装脚本不会拒绝这个卷名。

`.env` 里的库名和账号名是 `asset_ledger`，`PRODUCT_CODE` 是 `asset-ledger`，`DATABASE_URL` 的主机名是 `postgres`。应用默认从宿主机端口 `8010` 进入。compose 不把 PostgreSQL 的 5432 映射出来。

安装目录示例是 `/opt/asset-ledger`。该目录已有安装时，使用 `upgrade.sh`，不要再次执行 `install.sh`。升级和日常启动都走 `deploy/` 里的脚本，不在运行机构建或拉取镜像。不要执行 `docker compose down -v`，不要改卷名。

本版没有登录。只应在可信内网开放 `8010`。能打开该端口的人可以修改和删除台账。删除空间或资产后不能从页面恢复。删除前执行 `deploy/backup.sh`。备份里有 `db.sql` 和 `VERSION`。

应用就绪的判据是 `http://127.0.0.1:8010/healthz` 返回正文 `ok`。端口以 `.env` 的 `APP_PORT` 为准。
