# 机房/办公资产录入台账第 1 轮设计

本文只定规格和页面。不写 `app/`，不写《功能说明》正文，不改 `delivery-ledger/`。拟写入《功能说明》的草案见同目录 `design-asset-round1-spec-delta.md`。实现轮先把草案整篇贴成 `asset-ledger/功能说明.md`，再写代码。

产品放在独立目录 `asset-ledger/`。它记录机房和办公场所里的服务器、交换机、防火墙、硬盘：在线建空间、在线录入、导出 Excel。技术栈与离线部署方式对齐客户交付台账：FastAPI、Jinja2、SQLAlchemy、PostgreSQL 16、容器内 uvicorn、离线 `linux/amd64`。可信内网，本版没有登录。

矩阵、字段、导出列和验收句以草案条文为准。本文与草案写的是同一套规则。

## 1. 本版定什么

本版必须能用的能力：

- 在线创建空间，并按第 5 节的父子矩阵逐层挂接。类型是机房、机柜、仓库、办公区、柜子、工位。
- 录入资产。类型是服务器、交换机、防火墙、硬盘。每条资产有位置、资产编号、序列号、名称；网络设备另有 BMC IP、业务 IP、MAC。型号、位置备注、备注可空。
- 服务器、交换机、防火墙放在机柜的连续 U 位上，或放在仓库（含仓库下的柜子）。硬盘挂在某台服务器上，或放在仓库、柜子、办公区、工位。
- 资产列表和单个空间都能导出 `.xlsx`。
- 升级只在 `migrate.py` 末尾追加。已录入的空间和资产留在库里。

放到后续迭代，避免本版做成 CMDB 平台：登录和权限、自动发现、线缆和端口、机柜拖拽、正反面与半 U、厂商型号库、PDU 监控、Excel 导入、办公终端、货架类型、未定位资产、报废和借出、变更流水、第二块 MAC、IPv6、附件。

## 2. 和客户交付台账的关系

`delivery-ledger/` 继续是客户交付台账。本产品不读取它的表，不导入它的 Python 包，不修改它的规格、模板和迁移。两套应用各有自己的 `pyproject.toml`、镜像名、安装目录和数据库名。

运维对齐这些做法：compose 里只有 `app` 和 `postgres`；`postgres` 镜像标签是 `postgres:16`；`pull_policy: never`；宿主机不装 Python；运行机可以没有 DNS，也不访问 `registry-1.docker.io`；Apple Silicon 上打包必须产出单架构 `linux/amd64`；`/healthz` 作为升级完成的判据；pytest 连接 `DATABASE_URL` 指向的 PostgreSQL。

卷名按本轮要求固定为 `delivery_ledger_pgdata`，与客户交付台账的卷名相同。这是本轮已经拍板的字面值，实现时不要改成别的名字。同机同时挂载这一卷的风险见第 13 节，由测试轮决定是否在写业务代码前改判。

默认宿主机端口是 `8010`，容器内 uvicorn 仍监听 `8000`。库名是 `asset_ledger`。compose 项目名是 `asset-ledger`。安装目录示例是 `/opt/asset-ledger`。

## 3. 业界工具的共性，以及落在本产品上的取舍

看的是机房和库存录入里已经反复出现的结构，不是把这些产品搬进来。

| 工具 | 它实际在做什么 | 本台账采纳的部分 | 不搬进来的部分 |
| --- | --- | --- | --- |
| NetBox | Site → Location（可嵌套）→ Rack → Device。字段含 serial、asset tag、primary IP、OOB/BMC IP。硬盘等组件挂在 Device 下 | 空间逐层递进；设备挂到机柜或仓库；硬盘挂到服务器；资产编号、SN、BMC IP、业务 IP、MAC | RBAC、自动发现、线缆对端、厂商型号库、完整 IPAM |
| RackOps（BearDooks） | FastAPI + Jinja2 + SQLAlchemy。机柜正视图，Asset Tag、SN、管理 IP，以及审计 | 同一套服务端渲染栈；机柜按 U 从上到下展示占用；编号、SN、管理类地址 | 账号体系。审计流水放在后续迭代 |
| Rackbase | 多站点资产库存，面向 MSP，前后端分离 | 多空间并存，一份台账覆盖机房和办公 | 前后端分离，以及 MSP 工单 |
| RackTables REST API | Location → Row → Rack → Object → Allocation。接口强调移动时的业务规则校验 | 保存和移动都在服务端校验，不合法则整次不写库 | Row 这一层、分配工单、把 REST 当作主界面 |
| RackOps CMDB | 机房、机柜、在用和仓库设备，Excel 报表。实现是 Django + React | 机房、机柜、仓库这组位置，以及 Excel 导出 | Django、React，以及单独的在用/在库状态机。位置本身表示在架还是在库 |
| PMIS Enterprise | FastAPI + Jinja2 + OpenPyXL，做机柜和设备登记 | 这个栈组合：页面服务端渲染，Excel 用 OpenPyXL 写出 | 项目管理里的其余模块 |

交互上采纳这六条：

1. 先有空间，再把资产挂到允许的宿主上。宿主不合规则时整次拒绝。
2. 机柜用 U 位表达占用。页面给出只读的 U 表，录入用表单填写起始 U 和占用高度。
3. 硬盘是资产，不是服务器上的一段备注。它挂在服务器上时，服务器搬走，导出里的空间路径跟着服务器走。
4. 资产编号和序列号全局唯一。IP 只校验格式，本版不把地址做成 IPAM。
5. Excel 是当前清单的导出，列顺序固定。录入仍在页面上完成。
6. 服务端渲染，脚本不从外网加载。本版机柜表不依赖页面脚本。

落点约束：

- 依赖版本对齐客户交付台账已在用的 FastAPI、uvicorn、Jinja2、SQLAlchemy、psycopg，并增加 `openpyxl==3.1.5`、`et-xmlfile==2.0.0`。写入 `pyproject.toml`，打进离线 wheel。运行机不执行 pip。
- 结构迁移只在 `app/migrate.py` 末尾追加。语句只建表、加列、加兼容默认值。不删除已有业务行。
- 型号是一条可空文本，供导出时辨认设备。它不是厂商型号库，页面不提供型号下拉。

## 4. 信息架构

三个入口，顺序固定：首页、空间、资产。导出是按钮，不是第四个模块。

1. **首页**（`/`）。三个数：空间数、资产数、硬盘数。下面是最近录入的 20 条资产，链到资产详情。
2. **空间**（`/spaces`，详情 `/spaces/{id}`）。树按父子缩进。详情里是路径、子空间、本空间范围内的资产，机柜另有只读 U 表。
3. **资产**（`/assets`，详情 `/assets/{id}`）。筛选、表格、新建和编辑。列表和空间详情都可以导出。

没有登录页、账号菜单、发现任务、线缆图和型号库页面。

空库时，空间页提示先建立机房、仓库或办公区。资产页在还没有任何允许的宿主时，提示先创建空间。

## 5. 空间类型与父子关系

内部码与页面用词固定，机柜和柜子不要混用：

| 内部码 | 页面用词 | 这一层表示什么 |
| --- | --- | --- |
| `room` | 机房 | 上架空间的容器，本身不放资产 |
| `rack` | 机柜 | 19 英寸机柜，有 U 高 |
| `warehouse` | 仓库 | 在库设备的容器，本身可以放资产 |
| `office` | 办公区 | 办公场所，可以再套办公区 |
| `cabinet` | 柜子 | 储物柜、备件柜，不是机柜 |
| `desk` | 工位 | 人的工位 |

父级允许矩阵。行是要创建或移入的子类型，列是父级。空父级表示根。允许记为「可」，其余组合拒绝。

| 子类型 | 根 | 机房 | 机柜 | 仓库 | 办公区 | 柜子 | 工位 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 机房 | 可 |  |  |  |  |  |  |
| 机柜 |  | 可 |  |  |  |  |  |
| 仓库 | 可 |  |  |  |  |  |  |
| 办公区 | 可 |  |  |  | 可 |  |  |
| 柜子 |  |  |  | 可 | 可 |  |  |
| 工位 |  |  |  |  | 可 |  |  |

拒绝时的提示用子类型的页面用词：「这里不能放机柜」「这里不能放机房」「这里不能放仓库」「这里不能放办公区」「这里不能放柜子」「这里不能放工位」。

路径长度从根算到自身，最多 4。再往下挂时拒绝，提示「空间层级过深」。因此「办公区 / 办公区 / 办公区 / 工位」可以保存；再在最深的办公区下增加一层则不行。机房到机柜、仓库到柜子都只有两层，不受这个上限挤压。

名称在同一父级下忽略大小写后唯一。两个机房里的机柜可以都叫 `A01`。名称不能含 `/` 或 `\`，以便空间路径和导出文件名稳定。

空间类型创建后保持不变。父级可以改到矩阵允许的另一个节点，不能改到自己或自己的子孙。移动后，该空间以及其子孙上已经存在的资产必须仍然满足第 6 节；否则拒绝，父级保持原值，提示「移动后已有资产不能留在这里」。

机柜高度是 1 到 52 的整数，新建表单预填 42，以提交值为准。缩小时，若已有设备的最高 U 超过新高度，拒绝，提示「机柜高度小于已占用 U 位」。

删除空间要带确认。下面还有子空间时提示「下面还有空间」。本节点上还有直接放置的资产时提示「这里还有资产」。挂在服务器上的硬盘不算机柜上的直接资产；要拆掉机柜，先移走机柜里的设备。

用户说的「办公空间」在本版落成三种可创建节点：办公区、办公区下的柜子、工位。硬盘这三处都可以放。若测试认为办公空间只应是一个类型，应在实现前改这张矩阵。

## 6. 资产类型与位置宿主

| 内部码 | 页面用词 | 允许的宿主 |
| --- | --- | --- |
| `server` | 服务器 | 机柜（连续 U）；仓库节点；根是仓库的柜子 |
| `switch` | 交换机 | 与服务器相同 |
| `firewall` | 防火墙 | 与服务器相同 |
| `disk` | 硬盘 | 一台服务器；仓库节点；任意柜子；办公区；工位 |

机房节点、机柜上的硬盘、办公区里的服务器，都拒绝。提示分别是「服务器不能放在这里」「交换机不能放在这里」「防火墙不能放在这里」「硬盘不能放在这里」。

每条资产恰好有一个宿主：

- 放在空间上：`location_space_id` 有值，`mounted_on_asset_id` 为空。
- 硬盘挂在服务器上：`mounted_on_asset_id` 指向类型为服务器的资产，`location_space_id` 为空。目标不是服务器时提示「挂载目标不是服务器」。

服务器、交换机、防火墙不能挂到另一台资产上。硬盘不能再挂硬盘。

根的算法：沿父级走到没有父级的那个空间。柜子的根只会是仓库或办公区。根是仓库的柜子可以放服务器、交换机、防火墙和硬盘，表示箱子放在备件柜里，不占 U。根是办公区的柜子只放硬盘。

U 位只在宿主是机柜时使用：

- 起始 U、占用高度都是整数，都要填。占用高度至少为 1。
- 占用区间是闭区间 `[起始 U, 起始 U + 占用高度 - 1]`，整个区间必须落在 `1` 到该机柜高度之间，否则提示「U 位超出机柜」。
- 同一机柜内两个区间相交则提示「U 位重叠」，已有记录不变。
- 本版每台设备占满该 U 的整个宽度，只记正面这一档。
- 页面给服务器预填占用高度 2，给交换机和防火墙预填 1。缺省提交时拒绝，提示「请填写占用高度」或「请填写起始 U」，不用预填值偷偷补写。

仓库、柜子、办公区、工位以及「挂在服务器上」都不使用 U。这两项有值时提示「这里不使用 U 位」。

位置备注可空，最长 200。机柜里它不参与重叠计算。硬盘挂在服务器上时，用它记槽位，例如「槽位 2」。槽位不建单独的空间类型。

删除带有硬盘的服务器时拒绝，提示「请先移出硬盘」。把服务器挪到另一机柜的空闲 U，或挪进仓库后，硬盘的挂载关系不变。导出时硬盘的空间路径取它所挂服务器当时的空间路径。

本版不另设「在用 / 在库 / 报废」。在机柜里就是上架，在仓库范围内就是在库。

## 7. 核心字段与唯一性

### 7.1 空间

| 字段 | 要求 |
| --- | --- |
| 类型 | 第 5 节六种之一。创建后不变 |
| 名称 | 必填，去掉首尾空白后 1–100 字。不含 `/` 和 `\`。同一父级下忽略大小写唯一 |
| 父级 | 可空。非空时必须存在，且满足矩阵、深度和防环 |
| 机柜高度 | 仅机柜。1–52 的整数。其他类型为空 |
| 说明 | 可空，最长 2000 |
| 登记时间 | 应用写入，不可编辑 |

### 7.2 资产

| 字段 | 要求 |
| --- | --- |
| 资产编号 | 必填，去掉首尾空白后 1–64 字，中间不能有空白。忽略大小写后全局唯一 |
| 序列号 | 必填，去掉首尾空白后 1–128 字，中间不能有空白。忽略大小写后全局唯一。与资产编号互不占用对方的唯一性 |
| 名称 | 必填，1–200 字 |
| 类型 | 第 6 节四种之一。修改后连同现有宿主一起重新校验 |
| 型号 | 可空，最长 200。自由文本 |
| BMC IP | 可空。有值时必须是点分 IPv4。硬盘必须为空 |
| 业务 IP | 与 BMC IP 相同的格式规则。硬盘必须为空 |
| MAC | 可空。有值时是 6 字节，存小写冒号形式 `aa:bb:cc:dd:ee:ff`。硬盘必须为空 |
| 宿主 | 第 6 节。空间或服务器二选一 |
| 起始 U、占用高度 | 仅机柜宿主 |
| 位置备注 | 可空，最长 200 |
| 备注 | 可空，最长 4000 |
| 登记时间 | 应用写入，修改资产时不变 |

唯一性比较在去掉首尾空白并转成小写之后进行，库里保存去掉首尾空白、保留原大小写的文本。`Ab` 与 `ab` 视为同一个资产编号或同一个序列号。数据库用 `lower(资产编号)`、`lower(序列号)` 的唯一索引兜底，并发时也返回「资产编号已存在」或「序列号已存在」。

IP 和 MAC 不设唯一。两台设备可以暂存同一个地址。IPv4 不接受前导零，不接受主机名。MAC 输入接受冒号、连字符或 12 位连续十六进制，页面和导出都显示规范形式。

硬盘若填写了网络字段，按 BMC IP、业务 IP、MAC 的顺序只报第一个：「硬盘不记录 BMC」「硬盘不记录业务 IP」「硬盘不记录 MAC」。

资产编号与序列号是两套编号。本版不从序列号生成资产编号。

## 8. 校验规则

浏览器里能提交的值，服务端再查一次。任一规则失败则整次不写库，表单保留用户刚提交的内容。

检查顺序：

1. 必填、长度、空白、名称中的斜杠。
2. IP、MAC、机柜高度、U 的格式和范围。
3. 硬盘的网络字段必须为空。
4. 父子矩阵、路径深度、防环、宿主类型。
5. 资产编号、序列号、同级空间名称的唯一性。
6. U 重叠，以及缩小机柜时是否盖住已占用的 U。

因此格式错误优先于「已存在」。重叠检查放在同一事务里，排除正在保存的这一条自身。

直接提交删除且确认字段不是 `yes` 时拒绝，提示「请确认删除」，记录还在。

空间或资产不存在时，页面返回 404，文案是「没有这个空间」或「没有这个资产」。

当前库里如果已经有表 `deliveries`，进程在建表之前退出，日志包含「数据库卷与客户交付台账冲突」，不创建 `assets`，不写入 `schema_migration`。这是为了避免误挂到客户交付台账那个同名卷里的库。

## 9. Excel 导出

导出是只读的当前结果。本版页面没有上传 Excel 的入口。

只生成一个工作表，表名「资产」。第 1 行是列名，数据从第 2 行起。列顺序：

1. 资产编号
2. 序列号
3. 名称
4. 类型
5. 型号
6. 宿主种类
7. 空间路径
8. 起始U
9. 占用U
10. 挂载于资产编号
11. BMC IP
12. 业务 IP
13. MAC
14. 位置备注
15. 备注
16. 登记时间

类型、宿主种类使用页面用词。宿主种类是：机柜、仓库、柜子、办公区、工位、服务器。

空间路径用 ` / ` 连接从根到该空间的名称。硬盘挂在服务器上时，空间路径取服务器的路径，宿主种类写「服务器」，「挂载于资产编号」写那台服务器的资产编号，起始 U 和占用高度留空。路径中的空间若后来改名，下次导出用新名称。

起始 U、占用高度是整数单元格，没有 U 时留空。其余空字段是空单元格。登记时间按 `Asia/Shanghai`，格式 `YYYY-MM-DD HH:MM`。

排序按资产编号的小写字典序，再按编号。

两处入口，列完全一致：

- `GET /assets/export.xlsx` 使用资产列表当前的筛选：类型、空间、关键字三者同时生效。空间筛选包含该空间的全部子孙；并包含挂在「位于这些空间的服务器」上的硬盘。没有筛选时导出全部资产，文件名 `资产台账.xlsx`。有任一筛选时文件名 `资产台账-筛选.xlsx`。
- `GET /spaces/{id}/export.xlsx` 的范围等于在资产列表里按该空间筛选。文件名是 `资产台账-` 加上该空间名称；名称里不能做文件名的字符换成下划线。

筛选关键字忽略大小写，匹配资产编号、序列号、名称、型号的包含关系。列表每页 200 条，导出不受分页限制，写出全部命中行。用 openpyxl 的只写模式生成。

从某间机房导出时，包含这间机房各个机柜里的设备，以及挂在这些设备上的硬盘；不包含其他仓库里的硬盘。

## 10. 页面

页面由 Jinja2 在服务端渲染，语言是简体中文。表单沿用客户交付台账的做法：启动时修正把 UTF-8 表单体误按 Latin-1 解开的情况；已经是正常 Unicode 的值保持不变。

资产列表列：资产编号、序列号、名称、类型、位置、BMC IP、业务 IP、MAC。位置列写空间路径；硬盘挂在服务器上时写「服务器 {资产编号}」。

资产表单的位置先选宿主种类，再选具体空间或服务器。宿主种类随资产类型只留下第 6 节允许的项。选中机柜后才显示起始 U 和占用高度。没有任何合法宿主时，不提交空位置，提示「请先创建可以放置这种设备的空间」；若仍提交，拒绝为「请选择位置」。

机柜详情的 U 表从高 U 到 1 逐行显示，跨 U 设备在占用的每一行显示同一资产编号和名称。表是只读的，上架在资产表单里保存。

编辑与新建使用同一组校验。失败时原记录保持不变。

删除按钮提交到各自的删除地址，并带上确认字段。

路由：

| 方法与路径 | 作用 |
| --- | --- |
| `GET /` | 首页 |
| `GET /healthz` | 数据库可连接时返回 200，正文 `ok` |
| `GET /spaces`、`POST /spaces` | 空间树、创建 |
| `GET /spaces/{id}`、`POST /spaces/{id}` | 详情、修改 |
| `POST /spaces/{id}/delete` | 删除空间 |
| `GET /spaces/{id}/export.xlsx` | 导出该空间范围 |
| `GET /assets`、`GET /assets/new`、`POST /assets` | 列表、新建表单、创建 |
| `GET /assets/{id}`、`POST /assets/{id}` | 详情、修改 |
| `POST /assets/{id}/delete` | 删除资产 |
| `GET /assets/export.xlsx` | 按当前筛选导出 |

`/assets/new` 和 `/assets/export.xlsx` 要先于 `/assets/{id}` 注册。

## 11. 目录、迁移与离线部署

实现轮的目录：

```text
asset-ledger/
  app/                 main.py、db.py、models.py、migrate.py、domain.py、
                       services.py、routes.py、formtext.py、templating.py、
                       templates/、static/
  tests/
  deploy/              package.sh、install.sh、upgrade.sh、up.sh、backup.sh、restore.sh
  docs/                本轮这两份设计
  Dockerfile
  docker-compose.yml
  pyproject.toml
  VERSION              初版 0.1.0
  .env.example
  功能说明.md
  部署说明.md
  发布构建标准.md
```

本轮只新增 `docs/` 下的两份设计。

表：`spaces`、`assets`、`schema_migration`。父级、放置空间、挂载资产都是外键，删除用数据库的 RESTRICT 再挡一层。根空间的同名用 `parent_id IS NULL` 的部分唯一索引；非根用 `(parent_id, lower(name))` 的部分唯一索引。不要依赖「父级可空的普通唯一约束」，PostgreSQL 里多个空父级不会互相冲突。

`0.1.0` 表示初始表由启动时创建，并写入 `schema_migration`。此后每次改表只在 `MIGRATIONS` 末尾追加，已执行的版本不再执行。本版没有旧数据要回填。

compose 的卷：

```yaml
volumes:
  pgdata:
    name: delivery_ledger_pgdata
```

项目名 `asset-ledger`。`app` 镜像 `asset-ledger:${APP_VERSION:-0.1.0}`，端口 `${APP_PORT:-8010}:8000`。两个服务都设置 `TZ=Asia/Shanghai`，`pull_policy: never`。本版没有上传文件，compose 不挂附件目录。

`.env.example` 里的库名是 `asset_ledger`，主机名是 `postgres`。安装脚本生成随机的数据库账号和密码，库名保持 `asset_ledger`，文件权限 `600`。

打包对齐《客户交付台账发布构建标准》的架构条款，产品名换成资产台账：在能访问镜像站的机器上执行 `deploy/package.sh`；产物 `dist/asset-ledger-<版本>.tar.gz`；包内镜像只有 `asset-ledger:<版本>` 和 `postgres:16`；两者 `Architecture` 都是 `amd64`；`docker run --platform linux/amd64 … uname -m` 是 `x86_64`。Apple Silicon 上必须经过构建后的压扁，不能把 arm64 内容标成 amd64。运行机只 `docker load` 再 `compose up`。

升级替换程序和镜像，保留 `.env`、`backups/` 和卷 `delivery_ledger_pgdata`。禁止 `docker compose down -v`。升级前备份数据库。`/healthz` 成功才算升级完成。实现轮把这些句子写入本产品自己的《部署说明》和《发布构建标准》，不改客户交付台账那两份文档。

## 12. 验收要点

下面与草案第 9 节是同一组句子，实现轮的 pytest 按这组句子写。

1. 根上可以创建机房、仓库、办公区。根上创建机柜、柜子、工位时分别提示「这里不能放机柜」「这里不能放柜子」「这里不能放工位」，不产生记录。
2. 机房下可以创建机柜。机房下创建仓库、办公区、柜子、工位或另一间机房时拒绝。机柜、柜子、工位之下不能再创建空间。
3. 仓库下可以创建柜子，不能创建机柜、机房、仓库、办公区、工位。办公区下可以创建办公区、柜子、工位。
4. 「办公区 / 办公区 / 办公区 / 工位」可以保存。在已达 4 层的节点下继续创建时提示「空间层级过深」。
5. 同一父级下名称忽略大小写相同则提示「同级已有这个名称」。不同机房的机柜可以同名。名称含 `/` 或 `\` 时拒绝。
6. 修改空间类型时提示「类型创建后不能改」，原类型还在。移到矩阵不允许的父级时父级不变。移到自己的子孙下时提示「不能放到自己的下级」。移动会导致已有资产失去合法宿主时提示「移动后已有资产不能留在这里」。
7. 删除仍有子空间的节点提示「下面还有空间」。删除仍有直接资产的节点提示「这里还有资产」。确认字段不是 `yes` 时提示「请确认删除」。
8. 服务器、交换机、防火墙可以进入机柜并占用连续 U，也可以放在仓库节点或根为仓库的柜子。放到办公区、工位、根为办公区的柜子、机房节点时，提示里带上这种设备的页面用词，例如「服务器不能放在这里」。
9. 硬盘可以挂到服务器，也可以放在仓库、柜子、办公区、工位。放到机柜时提示「硬盘不能放在这里」。挂载目标不是服务器时提示「挂载目标不是服务器」。
10. 同一机柜 U 相交时提示「U 位重叠」。超出机柜高度时提示「U 位超出机柜」。非机柜位置带 U 时提示「这里不使用 U 位」。缺起始 U 或占用高度时分别提示「请填写起始 U」「请填写占用高度」。
11. 机柜高度改到已占用最高 U 之下时提示「机柜高度小于已占用 U 位」，高度不变。高度不在 1–52 时提示「机柜高度无效」。
12. 资产编号或序列号空白时分别提示「请填写资产编号」「请填写序列号」。忽略大小写后的重复分别提示「资产编号已存在」「序列号已存在」。中间有空格时分别提示「资产编号不能有空格」「序列号不能有空格」。
13. 非法 IP 提示「IP 格式不正确」。`AABBCCDDEEFF` 保存后显示为 `aa:bb:cc:dd:ee:ff`。硬盘填写 BMC IP 时提示「硬盘不记录 BMC」，记录不产生。两台服务器可以保存同一个业务 IP。
14. 服务器下仍有硬盘时删除提示「请先移出硬盘」。服务器换到另一机柜的空闲 U 之后，硬盘仍挂在这台服务器上，导出的空间路径变为新机柜的路径。
15. 导出表名「资产」，列名和顺序与第 9 节一致。只筛选硬盘时文件中的类型列都是「硬盘」。从某机房导出时含其机柜中的设备及这些设备上的硬盘，不含另一仓库中的硬盘。无筛选时文件名是 `资产台账.xlsx`。
16. 页面没有登录表单。数据库可连接时 `/healthz` 为 200，正文 `ok`。
17. 当前库已有表 `deliveries` 时，应用退出，日志含「数据库卷与客户交付台账冲突」，且不创建 `assets`。

## 13. 风险和本轮留给测试的挑战点

这些是已经拍板、但测试轮应当故意撞击的点。撞倒的条目在实现前改草案，不在编码时临时放宽。

| 风险 | 本设计怎么接 | 测试可以怎么挑战 |
| --- | --- | --- |
| 卷名 `delivery_ledger_pgdata` 与客户交付台账相同。同一 Docker 主机上，这个卷同时只能给一个 postgres 数据目录使用 | 字面值按用户要求保留。库名用 `asset_ledger`。见到表 `deliveries` 就拒绝启动，不建资产表 | 在已安装交付台账的机器上启动本产品，确认失败可见，且交付台账的表和卷都还在。若同机部署是现场条件，应在写代码前把卷名改判为独立名字，并写好旧卷不动的升级说明 |
| 办公空间被拆成办公区、柜子、工位 | 硬盘三种都能放。服务器不能放在办公区一侧 | 用「硬盘在某办公空间」的原始说法核对矩阵。若业务只想要一个叫办公空间的类型，本矩阵过细 |
| 仓库下的柜子可以放服务器 | 把「服务器可在仓库」解释为仓库节点及其备件柜，不占 U | 若柜子只应放硬盘和小件，第 6 节会放进不该上架的设备 |
| 机房下面不能建柜子 | 机房只作为机柜的父级。备件进仓库 | 机房内的备件柜在本版没有合法父级 |
| 路径最多 4 层 | 「楼 / 层 / 区 / 工位」刚好四层 | 园区、楼、层、区、工位是五层，会被「空间层级过深」拦住。放宽上限不需要改写已有行 |
| 只记一块 MAC | 字段就叫 MAC，一块，规范成小写冒号 | 服务器通常同时有 BMC MAC 和业务 MAC。本版会丢其中一块。加列必须是追加迁移 |
| IP 不唯一 | 台账记录填写值，不担任 IPAM | 两个在用地址相同会静默保存。若现场要防重，要另加规则和提示语 |
| 没有在用、报废、借出 | 位置表示在架或在库。删除是物理删除 | 误删不能从应用里恢复，只能靠升级备份。变更流水在后续迭代 |
| 机柜只读、整宽、只记正面 | 上架靠表单里的起始 U 和高度 | 与交付台账的拖拽机柜不同。半 U、背面和左右并排在本版会互相判重叠 |
| 槽位是位置备注 | 硬盘挂到服务器即可导出 | 没有槽位占用校验，两块盘可以写同一个槽位 |
| 型号是自由文本 | 避免厂商型号库 | 同一种设备会出现多种写法，导出无法按型号归并 |
| 本版只有导出 | 列顺序按导入也会用到的形状固定下来 | 现场若指望先填 Excel 再入库，本版没有这条路径 |
| 没有登录 | 与交付台账本版一样，依赖可信内网 | 任何能打开端口的人都能改和删 |
| 同名卷的启动检查只认 `deliveries` | 这是交付台账里稳定存在的业务表 | 若对方表名变了，检查会失效。检查不能改成「看见任何陌生表都退出」，否则后续本产品自己的加表也会被拦住 |

## 14. 后续迭代

实现本版时不要顺手做这些：登录和权限；SNMP、Nmap、自动发现；端口、网线、光纤；机柜拖拽、背面、半 U、左右并排；厂商型号下拉或型号库；PDU 和功耗采集；Excel 上传导入；办公终端、光模块等新资产类型；货架或库区类型；未填写位置的资产；报废、维修、借出状态；变更流水和回收站；BMC MAC 与业务 MAC 分列；IPv6；附件。

需要新增时，在 `migrate.py` 末尾追加版本，并在《功能说明》的结构版本列表里记同一句。已有资产编号、序列号和空间行保持原值。
