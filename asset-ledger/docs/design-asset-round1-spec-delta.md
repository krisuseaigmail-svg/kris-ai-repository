本文是拟整篇贴成 `asset-ledger/功能说明.md` 的条文。贴入之前不是已生效规格。本轮不创建《功能说明》正文，不写 `app/`，不改 `delivery-ledger/`。

写法以可执行的规格为准。范围外的能力写在文末「后续迭代」。结构版本若在贴入时 `0.1.0` 已被占用，改用下一个未占用版本，下面各处一起改。

## 1. 目标

资产台账记录机房和办公场所中的服务器、交换机、防火墙和硬盘，供可信内网里的内部人员在线录入，并导出 Excel。

一台资产有资产编号、序列号和位置。服务器、交换机、防火墙放在机柜的 U 位上，或放在仓库里。硬盘放在某台服务器里，或放在仓库、柜子、办公区、工位。

应用放在独立目录 `asset-ledger/`。客户交付台账仍在 `delivery-ledger/`。两套产品不共用代码，不互相写入业务数据。

## 2. 技术约束

- 目录是 `asset-ledger/`。依赖写在 `asset-ledger/pyproject.toml`。
- Python、FastAPI、Jinja2、SQLAlchemy、PostgreSQL 16。应用在容器内用 uvicorn 监听 `8000`。
- 界面语言为简体中文。页面由服务端渲染。表单中文按 UTF-8 还原：应用启动时修正把 `application/x-www-form-urlencoded` 里的 UTF-8 误按 Latin-1 解开的情况；已经是正常 Unicode 的值保持不变。
- 部署在可信内网。本版页面没有登录。
- 宿主机是 SUSE Linux Enterprise Server 15.6（x86_64），已经安装 Docker。宿主机不安装 Python。
- 用 `asset-ledger/docker-compose.yml` 启动 `app` 和 `postgres` 两个服务。项目名是 `asset-ledger`。`postgres` 使用镜像标签 `postgres:16`。两个服务的 `pull_policy` 都是 `never`。
- 数据库连接从 `DATABASE_URL` 读取。主机名是 `postgres`。库名是 `asset_ledger`。仓库提供使用占位符的 `.env.example`。安装时生成随机数据库账号和密码，权限 `600`，库名保持 `asset_ledger`。
- compose 卷的 `name` 固定为 `delivery_ledger_pgdata`。这是本产品数据卷的名字。升级、备份和恢复都不更换这个名字，也不执行会删除该卷的命令。
- 默认把容器的 `8000` 映射到宿主机 `8010`，由 `APP_PORT` 覆盖。两个服务的时区都是 `Asia/Shanghai`。
- 本版没有上传文件，compose 不挂附件目录。
- `app` 启动时先做第 2.1 节的库检查，再连接并创建还不存在的本产品表。已有库按 `app/migrate.py` 里尚未执行的版本补结构。
- 结构版本记在 `schema_migration`。`migrate.py` 只在列表末尾追加。已经执行过的版本不再执行。语句只新增表、新增列，或做不删除用户数据的兼容变更。当前记录：
  - `0.1.0`：初始表 `spaces`、`assets`，由启动时创建。
- Excel 使用 `openpyxl==3.1.5` 与 `et-xmlfile==2.0.0`。二者写入 `pyproject.toml`，并随离线镜像发布。运行机不单独安装。
- 发布包在开发机上由 `deploy/package.sh` 生成，路径为 `dist/asset-ledger-<版本>.tar.gz`。包内应用镜像和 `postgres:16` 都是单架构 `linux/amd64`。在 Apple Silicon 上打包时同样产出这一架构：镜像 `Architecture` 为 `amd64`，且 `uname -m` 为 `x86_64`。运行机可以没有 DNS，也不访问 `registry-1.docker.io`；安装和升级只加载包内镜像。
- 用 pytest 覆盖第 9 节。测试连接 PostgreSQL，连接串来自 `DATABASE_URL`。

### 2.1 启动时的库检查

建表之前检查当前连接的库。若已存在表 `deliveries`，进程退出，日志包含「数据库卷与客户交付台账冲突」。此时不创建 `spaces` 和 `assets`，不写入 `schema_migration`。

本产品自己的后续加表不使用 `deliveries` 这个表名。

## 3. 对象关系

```text
空间（机房 / 机柜 / 仓库 / 办公区 / 柜子 / 工位）
  └── 子空间（按第 4 节矩阵）
资产
  ├── 放在一个空间上（服务器、交换机、防火墙、硬盘）
  └── 或挂在一台服务器上（仅硬盘）
```

硬盘挂在服务器上时，不另记空间外键。它的空间路径始终等于那台服务器当前的空间路径。

空间删除、资产删除都要提交确认。仍有子空间、仍有直接放置的资产、或服务器上仍有硬盘时，删除不生效。

## 4. 空间

空间类型和页面用词：

| 内部码 | 页面用词 |
| --- | --- |
| `room` | 机房 |
| `rack` | 机柜 |
| `warehouse` | 仓库 |
| `office` | 办公区 |
| `cabinet` | 柜子 |
| `desk` | 工位 |

### 4.1 父子关系

行是子类型，列是父级。空父级是根。「可」表示允许创建和移入，其余组合拒绝。

| 子类型 | 根 | 机房 | 机柜 | 仓库 | 办公区 | 柜子 | 工位 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 机房 | 可 |  |  |  |  |  |  |
| 机柜 |  | 可 |  |  |  |  |  |
| 仓库 | 可 |  |  |  |  |  |  |
| 办公区 | 可 |  |  |  | 可 |  |  |
| 柜子 |  |  |  | 可 | 可 |  |  |
| 工位 |  |  |  |  | 可 |  |  |

拒绝提示：

- 「这里不能放机房」
- 「这里不能放机柜」
- 「这里不能放仓库」
- 「这里不能放办公区」
- 「这里不能放柜子」
- 「这里不能放工位」

从根到该空间，包含自身，最多 4 层。超出时拒绝，提示「空间层级过深」，不产生新节点。

名称必填。去掉首尾空白后长度为 1–100，且不能包含 `/` 或 `\`。同一父级下，名称忽略大小写后唯一；重复时提示「同级已有这个名称」。不同父级下可以同名。根节点之间也按同级比较。

说明可空，最长 2000。超过长度时提示「说明过长」。名称为空时提示「请填写名称」。名称过长时提示「名称过长」。含 `/` 或 `\` 时提示「名称不能含斜杠」。

类型在创建时确定，之后保持不变。提交了别的类型时提示「类型创建后不能改」，原类型还在。

修改父级时，新父级必须存在并满足上表，路径长度仍不超过 4，且新父级不是自己或自己的子孙。移到自己的子孙下时提示「不能放到自己的下级」。移动之后，该空间及子孙上已有资产若不再满足第 5 节，拒绝移动，提示「移动后已有资产不能留在这里」，父级保持原值。

只有机柜有高度。高度是 1 到 52 的整数，含两端。新建表单预填 42，保存以提交值为准。缺高度时提示「请填写机柜高度」。超出范围时提示「机柜高度无效」。其他类型的高度为空。把高度改到小于本机柜已有设备最高占用 U 时拒绝，提示「机柜高度小于已占用 U 位」，高度保持原值。

删除须带确认值 `yes`。未带或值不是 `yes` 时提示「请确认删除」，空间还在。存在子空间时提示「下面还有空间」。存在直接放置在本空间上的资产时提示「这里还有资产」。两种情况下空间都还在。

## 5. 资产与位置

资产类型和页面用词：

| 内部码 | 页面用词 |
| --- | --- |
| `server` | 服务器 |
| `switch` | 交换机 |
| `firewall` | 防火墙 |
| `disk` | 硬盘 |

### 5.1 宿主

每条资产恰好有一个宿主。

放在空间上时，空间外键有值，挂载资产外键为空。挂在服务器上时相反，并且只有硬盘可以这样挂。挂载目标不存在或类型不是服务器时，提示「挂载目标不是服务器」。

允许的组合：

| 资产 | 机柜，占连续 U | 仓库节点 | 柜子，且根空间是仓库 | 柜子，且根空间是办公区 | 办公区 | 工位 | 服务器 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 服务器 | 可 | 可 | 可 |  |  |  |  |
| 交换机 | 可 | 可 | 可 |  |  |  |  |
| 防火墙 | 可 | 可 | 可 |  |  |  |  |
| 硬盘 |  | 可 | 可 | 可 | 可 | 可 | 可 |

根空间是沿父级向上、父级为空的那个空间。机房节点不能直接放置资产。

不允许的组合拒绝，提示「服务器不能放在这里」「交换机不能放在这里」「防火墙不能放在这里」或「硬盘不能放在这里」。未选择宿主时提示「请选择位置」。还没有任何一种合法空间可供当前类型选择时，表单提示「请先创建可以放置这种设备的空间」。

### 5.2 U 位

U 位只用于放在机柜上的服务器、交换机和防火墙。

起始 U 和占用高度都是整数，并且都要提交。占用高度至少为 1。占用区间是闭区间，从起始 U 到「起始 U + 占用高度 - 1」，整个区间落在 1 和该机柜高度之间。超出时提示「U 位超出机柜」。同一机柜上与另一条资产的区间相交时提示「U 位重叠」，已有资产的 U 不变。检查在保存事务中完成，并排除正在修改的这一条。

缺起始 U 时提示「请填写起始 U」。缺占用高度时提示「请填写占用高度」。

新建表单上，服务器的占用高度预填 2，交换机和防火墙预填 1。用户清空后提交，按上一行的提示拒绝，不把预填值写进库。

放在仓库、柜子、办公区、工位，或挂在服务器上时，起始 U 和占用高度都为空。有值则提示「这里不使用 U 位」。

本版按机柜正面的整宽 U 记录。同一 U 上只放一条资产。

### 5.3 硬盘与服务器一起走

硬盘挂在服务器上时，位置备注可用来写槽位。槽位不参与唯一性。

删除仍挂有硬盘的服务器时拒绝，提示「请先移出硬盘」，服务器和硬盘都还在。

服务器改到另一个允许的宿主之后，这些硬盘的挂载目标不变。导出中硬盘的空间路径改为服务器的新路径。

把服务器改成硬盘、交换机或防火墙时，若它上面还有硬盘，同样提示「请先移出硬盘」，类型保持为服务器。

## 6. 字段与唯一性

资产字段：

| 字段 | 要求 |
| --- | --- |
| 资产编号 | 必填。去掉首尾空白后 1–64 字，中间不能有空白。忽略大小写后在全部资产中唯一 |
| 序列号 | 必填。去掉首尾空白后 1–128 字，中间不能有空白。忽略大小写后在全部资产中唯一 |
| 名称 | 必填，去掉首尾空白后 1–200 字 |
| 类型 | 第 5 节四种之一 |
| 型号 | 可空，最长 200 |
| BMC IP | 可空。有值时为点分十进制 IPv4，四段都是 0–255 的十进制整数，不带前导零 |
| 业务 IP | 与 BMC IP 相同 |
| MAC | 可空。输入可以是冒号分隔、连字符分隔或 12 位连续十六进制。保存为小写冒号形式，共 17 个字符 |
| 位置备注 | 可空，最长 200 |
| 备注 | 可空，最长 4000 |
| 登记时间 | 创建时写入，以后修改不改变。时区 `Asia/Shanghai` |

库中保存去掉首尾空白后的原文大小写。唯一索引建在小写形式上，并发冲突与普通重复使用同一提示。

提示用语：

- 资产编号为空：「请填写资产编号」
- 序列号为空：「请填写序列号」
- 资产名称为空：「请填写名称」
- 资产编号过长：「资产编号过长」
- 序列号过长：「序列号过长」
- 名称过长：「名称过长」
- 型号过长：「型号过长」
- 位置备注过长：「位置备注过长」
- 备注过长：「备注过长」
- 资产编号中间有空白：「资产编号不能有空格」
- 序列号中间有空白：「序列号不能有空格」
- 资产编号重复：「资产编号已存在」
- 序列号重复：「序列号已存在」
- IP 不合法：「IP 格式不正确」
- MAC 不合法：「MAC 格式不正确」

硬盘的 BMC IP、业务 IP、MAC 必须为空。按这个顺序检查，只提示第一个：「硬盘不记录 BMC」「硬盘不记录业务 IP」「硬盘不记录 MAC」。

BMC IP、业务 IP、MAC 可以与另一条资产相同。

资产编号和序列号互不替代。一条资产的编号可以与另一条资产的序列号文本相同。

一次保存中有多项错误时，按下面的顺序返回第一个提示，整次不写库：

1. 必填、长度、空白和斜杠。
2. IP、MAC、机柜高度和 U 的格式与范围。
3. 硬盘的网络字段。
4. 空间父子关系、路径深度、防环和资产宿主。
5. 资产编号、序列号、同级空间名称的唯一性。
6. U 位重叠，以及机柜高度小于已占用 U。

## 7. 页面

导航是首页、空间、资产。

首页显示空间数、资产数、硬盘数，以及最近创建的 20 条资产。每条链到该资产。

空间列表按父子缩进显示全部空间。新建根空间时，类型只有机房、仓库、办公区。空间详情显示从根开始的路径、类型、说明、子空间和本范围资产。添加子空间时，类型下拉只含第 4.1 节允许的子类型。机柜详情显示高度，以及从高 U 到 1 的只读占用表；跨越多 U 的设备在每一行显示同一资产编号和名称。空 U 只显示 U 号。

资产列表显示资产编号、序列号、名称、类型、位置、BMC IP、业务 IP、MAC。位置是空间路径；挂在服务器上的硬盘显示「服务器 」加那台服务器的资产编号。筛选有类型、空间和关键字，三者同时生效。关键字忽略大小写，匹配资产编号、序列号、名称和型号。空间筛选包含该空间的子孙，以及挂在这些空间中的服务器上的硬盘。列表每页 200 条。

资产新建和编辑使用同一组字段和同一套校验。保存失败时已提交的内容留在表单中，原记录不变。

空间或资产不存在时返回 404。空间的页面文案是「没有这个空间」，资产是「没有这个资产」。

路由：

- `GET /` 首页
- `GET /healthz` 数据库可连接时返回 200，正文是 `ok`
- `GET /spaces`、`POST /spaces` 空间列表和创建
- `GET /spaces/{id}`、`POST /spaces/{id}` 空间详情和修改
- `POST /spaces/{id}/delete` 删除空间
- `GET /spaces/{id}/export.xlsx` 导出该空间范围
- `GET /assets`、`GET /assets/new`、`POST /assets` 资产列表、新建表单和创建
- `GET /assets/{id}`、`POST /assets/{id}` 资产详情和修改
- `POST /assets/{id}/delete` 删除资产
- `GET /assets/export.xlsx` 按列表筛选导出

`/assets/new`、`/assets/export.xlsx` 优先于按编号取出资产的路由。

## 8. Excel

资产列表和空间详情可以导出当前范围。页面没有上传 Excel 的入口。

文件是一个工作表，表名「资产」。第 1 行依次为：

资产编号、序列号、名称、类型、型号、宿主种类、空间路径、起始U、占用U、挂载于资产编号、BMC IP、业务 IP、MAC、位置备注、备注、登记时间。

类型使用第 5 节的页面用词。宿主种类使用：机柜、仓库、柜子、办公区、工位、服务器。

空间路径从根到该空间，名称之间用 ` / ` 连接。硬盘挂在服务器上时，空间路径等于服务器的空间路径，宿主种类为「服务器」，挂载于资产编号为服务器的资产编号，起始 U 与占用高度为空。

起始 U 和占用高度在有值时写成整数，没有时单元格为空。其他空字段也是空单元格。登记时间的格式是 `YYYY-MM-DD HH:MM`，时区是 `Asia/Shanghai`。

行序按资产编号忽略大小写的字典序，再按资产编号原文字。

列表导出服从第 7 节的筛选，并且包含全部命中行，不受 200 条分页限制。没有任何筛选时，下载文件名为 `资产台账.xlsx`。有筛选时文件名为 `资产台账-筛选.xlsx`。

空间详情导出的范围，等于资产列表以该空间为筛选条件的范围。文件名是 `资产台账-` 加上空间名称；名称中不能用于文件名的字符替换为下划线。

从一间机房导出时，包含这间机房中各机柜上的设备，以及挂在这些设备上的硬盘，不包含位于其他仓库的硬盘。

## 9. 验收

1. 在根上创建机房、仓库、办公区可以保存。在根上创建机柜、柜子、工位时分别提示「这里不能放机柜」「这里不能放柜子」「这里不能放工位」，数据库里没有这三条。
2. 机房下可以创建机柜。机房下创建仓库、办公区、柜子、工位或第二间机房时拒绝，机房下除已成功的机柜外没有新节点。机柜、柜子、工位下创建任何空间都拒绝。
3. 仓库下可以创建柜子。仓库下创建机柜、机房、仓库、办公区或工位时拒绝。办公区下可以创建办公区、柜子和工位。
4. 连续三层办公区，最底层下的工位可以保存。此时路径长度为 4。在路径长度已经是 4 的节点下再创建空间时提示「空间层级过深」，节点数不变。
5. 同一父级下把名称改成与同级现有名称仅大小写不同的值时，提示「同级已有这个名称」，原名称还在。两个机房下的机柜可以使用同一个名称。名称含 `/` 或 `\` 时提示「名称不能含斜杠」。
6. 修改已有空间的类型时提示「类型创建后不能改」，类型不变。把机柜移到仓库下时父级不变。把空间的父级设为自己的子孙时提示「不能放到自己的下级」。把仍放着服务器的仓库柜子移到办公区下时提示「移动后已有资产不能留在这里」，父级仍是仓库。
7. 删除仍有子空间的空间时提示「下面还有空间」。删除仍有直接资产的空间时提示「这里还有资产」。删除请求的确认值不是 `yes` 时提示「请确认删除」。这三种情况下原空间还在。
8. 服务器、交换机、防火墙可以保存在机柜的合法 U 上，可以保存在仓库节点上，也可以保存在根为仓库的柜子里。保存到办公区、工位、根为办公区的柜子或机房节点时拒绝，提示分别为「服务器不能放在这里」「交换机不能放在这里」「防火墙不能放在这里」，不产生资产。
9. 硬盘可以挂到一台服务器上，也可以放在仓库、柜子、办公区、工位。放在机柜上时提示「硬盘不能放在这里」。挂载目标是交换机、防火墙或另一块硬盘时提示「挂载目标不是服务器」。
10. 同一机柜中两条资产的 U 区间相交时，后保存的那次提示「U 位重叠」，先保存的 U 不变。起始 U 加占用高度超出机柜高度时提示「U 位超出机柜」。仓库中的服务器若提交了起始 U，提示「这里不使用 U 位」。缺起始 U 时提示「请填写起始 U」。缺占用高度时提示「请填写占用高度」。
11. 已有设备占用到第 12U 时，把机柜高度改为 10，提示「机柜高度小于已占用 U 位」，高度仍是原值。高度为 0 或 53 时提示「机柜高度无效」。
12. 资产编号为空白时提示「请填写资产编号」。序列号为空白时提示「请填写序列号」。已有编号 `Ab` 时再保存 `ab`，提示「资产编号已存在」。序列号同样忽略大小写。资产编号或序列号中间含空格时，分别提示「资产编号不能有空格」「序列号不能有空格」。
13. 业务 IP 为 `192.168.001.1` 或 `bmc` 时提示「IP 格式不正确」。MAC 输入 `AABBCCDDEEFF` 后，页面和导出都是 `aa:bb:cc:dd:ee:ff`。硬盘填写 BMC IP 时提示「硬盘不记录 BMC」，不产生该硬盘。两台服务器保存同一个业务 IP 时两条都在。
14. 服务器上还有硬盘时删除服务器，提示「请先移出硬盘」，两条都还在。把这台服务器改到另一机柜的空闲 U 后，硬盘的挂载目标仍是它。导出里该硬盘的空间路径是新机柜的路径，挂载于资产编号是这台服务器的资产编号。
15. 无筛选导出的工作表名为「资产」，第 1 行 16 列与第 8 节一致，文件名为 `资产台账.xlsx`。类型筛选为硬盘时，数据行的类型都是「硬盘」，文件名为 `资产台账-筛选.xlsx`。从某机房导出时，含该机房机柜内的设备及其硬盘，不含只放在其他仓库的硬盘。
16. 首页、空间页和资产页都没有登录表单。数据库可连接时，`GET /healthz` 返回 200，正文是 `ok`。
17. 连接到已有表 `deliveries` 的库时，应用退出，日志含「数据库卷与客户交付台账冲突」，该库中没有新建的 `assets` 表。

## 10. 后续迭代

以后的版本可以在本节增加能力。增加表或列时，在 `migrate.py` 末尾追加结构版本，已有空间和资产的编号、序列号、名称和位置保持原值。

后续迭代包括：登录和权限；自动发现；端口、网线和光纤；机柜拖拽、背面和半 U；厂商型号库；PDU 监控；Excel 导入；办公终端等新的资产类型；货架或库区；尚未指定位置的资产；报废、维修和借出；变更流水；BMC MAC 与业务 MAC 分列；IPv6；附件。
