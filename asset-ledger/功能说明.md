# 机房/办公资产录入台账功能说明

本文是实现规格。按本文实现供可信内网使用的 Web 应用，代码放在独立目录 `asset-ledger/`。

`docs/` 中的各轮设计和测试报告不是实现输入。与本文冲突时以本文为准。打包与升级的硬性条款见《发布构建标准》，现场步骤与红线见《部署说明》。

## 1. 目标

资产台账记录机房和办公场所中的服务器、交换机、防火墙和硬盘，供内部人员在线录入，并导出 Excel。

一台资产有资产编号、序列号和位置。服务器、交换机、防火墙放在机柜的 U 位上，或放在仓库里（含仓库下的柜子）。硬盘放在某台服务器里，或放在仓库、柜子、办公区、工位。

客户交付台账仍在 `delivery-ledger/`。两套产品不共用代码，不互相写入业务数据。

## 2. 技术约束

- 目录是 `asset-ledger/`。依赖写在 `pyproject.toml`。
- Python 3.12、FastAPI、Jinja2、SQLAlchemy、PostgreSQL 16。应用在容器内用 uvicorn 监听 `8000`。基础镜像是 `python:3.12-slim`。
- 界面语言为简体中文。页面由服务端渲染。表单中文按 UTF-8 还原：应用启动时修正把 `application/x-www-form-urlencoded` 里的 UTF-8 误按 Latin-1 解开的情况；已经是正常 Unicode 的值保持不变。
- 部署在可信内网。本版页面没有登录。
- 宿主机是 SUSE Linux Enterprise Server 15.6（x86_64），已经安装 Docker。宿主机不安装 Python，也不使用宿主机上已有的 PostgreSQL。
- `docker-compose.yml` 的顶层 `name` 是 `asset-ledger`。脚本侧始终 `docker compose -p asset-ledger`。`postgres` 镜像标签是 `postgres:16`。`app` 与 `postgres` 的 `pull_policy` 都是 `never`。`postgres` 不写 `ports`，不把 5432 映射到宿主机。`postgres` 的 `entrypoint` 是 `["/bin/bash", "/pg-guard.sh"]`，`command` 是 `["postgres"]`。只改 entrypoint、不写这条 command 时，Compose 不会带上镜像 CMD，包装进程没有参数，会立刻以 0 退出，健康检查失败。`postgres` 的 healthcheck 为 `["CMD-SHELL", "pg_isready -U $$POSTGRES_USER -d $$POSTGRES_DB"]`，间隔 5s，超时 5s，重试 20 次。`app` 的 `depends_on` 为 postgres 且 `condition: service_healthy`。两个服务都可以 `restart: unless-stopped`。
- 数据库连接从 `DATABASE_URL` 读取。主机名是 `postgres`。库名和账号名是 `asset_ledger`。`PRODUCT_CODE` 为 `asset-ledger`。
- compose 卷的 `name` 固定为 `delivery_ledger_pgdata`。本产品独占该卷。禁止与客户交付台账在同一 Docker 宿主机上挂载它。不更换这个名字，也不执行会删除该卷的命令。
- 默认把容器的 `8000` 映射到宿主机 `8010`，由 `APP_PORT` 覆盖。两个服务的时区都是 `Asia/Shanghai`。
- 本版没有上传文件，compose 不挂附件目录。
- 支持的启动路径只有 `deploy/install.sh`、`deploy/upgrade.sh`、`deploy/up.sh`。三条都 source `deploy/lib.sh`，先调用其中的 `assert_volume_exclusive`，通过后才 `compose up`。禁止在运行机直接 `docker compose up`。
- postgres 容器的入口是 `deploy/pg-guard.sh`，不是镜像自带的入口。见第 2.3 节。
- `app` 启动时先做第 2.2 节，再创建还不存在的本产品表。已有库按 `app/migrate.py` 补结构。
- 结构版本记在 `schema_migration`。`migrate.py` 只在列表末尾追加。已经执行过的版本不再执行。语句只新增表、新增列，或做不删除用户数据的兼容变更。当前记录：
  - `0.1.0`：初始表 `spaces`、`assets`，由启动时创建。
- 主键是数据库生成的整数。
- 根空间的同名使用 `parent_id IS NULL` 的部分唯一索引；非根使用 `(parent_id, lower(name))` 的部分唯一索引。资产编号、序列号各自有 `lower(...)` 的唯一索引。
- 父级、放置空间、挂载资产是外键，数据库侧为 RESTRICT。完整性错误按第 4.3 节和第 6 节译成中文，HTTP 400，不是 500。
- Excel 使用 `openpyxl==3.1.5` 与 `et-xmlfile==2.0.0`。运行依赖随离线镜像发布。运行机不执行 pip。
- 校验失败时 HTTP 400，页面含规定的那一句提示，数据库不变。创建或修改成功时 303 到该条详情。对象不存在时 HTTP 404。
- 用 pytest 覆盖第 9 节。连接串的库名是 `asset_ledger_test`，指向独立的 PostgreSQL。不得使用安装目录 `.env` 里的现场库，也不得把测试指到卷 `delivery_ledger_pgdata` 上的业务库。该实例在普通用例中没有名为 `ledger` 的库，也没有任何库含 `public.deliveries`。

运行依赖版本：`fastapi==0.115.6`、`uvicorn==0.32.1`、`jinja2==3.1.4`、`sqlalchemy==2.0.36`、`psycopg[binary]>=3.2.4`、`python-multipart==0.0.17`、`itsdangerous==2.2.0`、`openpyxl==3.1.5`、`et-xmlfile==2.0.0`。

应用因第 2.2 节退出时，进程的 stderr 含该节规定的原句。`docker compose logs app` 能读到这些句子。`restart: unless-stopped` 可以保留，但不得换掉或吞掉这几句日志。

### 2.1 挂载卷之前

`assert_volume_exclusive` 只定义在 `deploy/lib.sh`。`install.sh`、`upgrade.sh`、`up.sh` 在任何 `compose up` 之前调用它，不得各自再写一份检查。

`compose` 函数固定为：

```bash
compose() {
  docker compose -p asset-ledger --project-directory "$INSTALL_DIR" "$@"
}
```

函数按下面的顺序执行。失败时退出码非 0，不 up，不 `docker volume rm`，不 `docker compose down -v`，不停止、不删除客户交付台账的容器。

```bash
assert_volume_exclusive() {
  if [ -n "${COMPOSE_PROJECT_NAME:-}" ] && [ "$COMPOSE_PROJECT_NAME" != "asset-ledger" ]; then
    echo "COMPOSE_PROJECT_NAME 必须是 asset-ledger" >&2
    exit 1
  fi
  export COMPOSE_PROJECT_NAME=asset-ledger

  for id in $(docker ps -aq); do
    [ -n "$id" ] || continue
    project=$(docker inspect -f '{{index .Config.Labels "com.docker.compose.project"}}' "$id" 2>/dev/null || true)
    mounts=$(docker inspect -f '{{range .Mounts}}{{println .Name}}{{end}}' "$id" 2>/dev/null || true)
    config_image=$(docker inspect -f '{{.Config.Image}}' "$id" 2>/dev/null || true)
    image_id=$(docker inspect -f '{{.Image}}' "$id" 2>/dev/null || true)
    repo_refs=$(docker image inspect -f '{{range .RepoTags}}{{println .}}{{end}}{{range .RepoDigests}}{{println .}}{{end}}' "$image_id" 2>/dev/null || true)
    refs="$config_image
$repo_refs"
    while IFS= read -r ref; do
      [ -n "$ref" ] || continue
      case "$ref" in
        sha256:*) continue ;;
      esac
      base=${ref%@*}
      base=${base%:*}
      name=${base##*/}
      if [ "$name" = "delivery-ledger" ]; then
        echo "禁止与客户交付台账同机部署" >&2
        exit 1
      fi
    done <<EOF
$refs
EOF
    if [ "$project" = "delivery-ledger" ]; then
      echo "禁止与客户交付台账同机部署" >&2
      exit 1
    fi
    while IFS= read -r mount_name; do
      if [ "$mount_name" = "delivery_ledger_pgdata" ] && [ "$project" != "asset-ledger" ]; then
        echo "禁止与客户交付台账同机部署" >&2
        exit 1
      fi
    done <<EOF
$mounts
EOF
  done

  if docker volume inspect delivery_ledger_pgdata >/dev/null 2>&1; then
    vproject=$(docker volume inspect delivery_ledger_pgdata --format '{{if .Labels}}{{index .Labels "com.docker.compose.project"}}{{end}}' 2>/dev/null || true)
    if [ "$vproject" != "asset-ledger" ]; then
      echo "卷 delivery_ledger_pgdata 不属于本产品，拒绝挂载" >&2
      exit 1
    fi
  fi
}
```

镜像引用只剩 `sha256:`、无法得到仓库名时，这一条不单独判为客户交付台账，也不得因此跳过挂载检查和卷标签检查。卷标签与第 2.3 节的标记文件仍然生效。

只把 `delivery-ledger` 镜像 load 进本机、还没有容器、卷也还不存在时，本函数不拒绝。随后禁止再安装客户交付台账，见《部署说明》。那一次后装不会被本产品自动变成失败。

### 2.2 建表之前

应用在创建 `spaces`、`assets` 和写入 `schema_migration` 之前完成下面的算法。失败则进程退出码非 0，不建这些表，不写 `schema_migration`。

1. 环境变量 `PRODUCT_CODE` 恰好是 `asset-ledger`。否则日志含「PRODUCT_CODE 必须是 asset-ledger」。
2. 用与业务库相同的用户和密码连接数据库 `postgres`，不是只连接 `asset_ledger`。连不上：日志含「无法检查数据库卷归属」。
3. 执行 `SELECT datname FROM pg_database WHERE datallowconn AND NOT datistemplate`。结果里有 `ledger`：日志含「数据库卷与客户交付台账冲突」，退出。
4. 对第 3 步的每一个 `datname`（含 `postgres` 和 `asset_ledger`）再建立一条到该库的连接，执行 `SELECT to_regclass('public.deliveries') IS NOT NULL`。任一库为真：同一句冲突日志，退出。返回 `NULL` 表示没有该表，继续下一个库。
5. 禁止用维护库上的 `pg_tables` 或 `information_schema.tables` 代替第 4 步。只在 `asset_ledger` 里找不到 `deliveries`，不能使启动继续建表。

本产品不创建名为 `ledger` 的库，不创建名为 `deliveries` 的表。其它表名不触发第 3、4 步。`PRODUCT_CODE` 不能代替第 2.1 节和第 2.3 节。

`/healthz` 在业务库可连接且本节已通过时返回 200，响应体去掉首尾空白后是 `ok`。检查未通过时进程不提供该响应。

### 2.3 postgres 启动包装

compose 的 `postgres` 服务把 `./deploy/pg-guard.sh` 只读挂到 `/pg-guard.sh`，`entrypoint` 是 `["/bin/bash", "/pg-guard.sh"]`，`command` 是 `["postgres"]`。官方入口路径是 `/usr/local/bin/docker-entrypoint.sh`。不增加第三张镜像。包装脚本把 `command` 的参数交给官方入口；没有 `postgres` 这个参数时官方入口不会拉起数据库。

数据目录是 `/var/lib/postgresql/data`。标记文件是该目录下的普通文件 `asset_ledger.owner`。合法内容是一行 `asset-ledger`：去掉文件末尾至多一个换行后，剩余字节恰好是 `asset-ledger`。

包装按这个顺序：

1. 数据目录没有 `PG_VERSION`（空目录，或只有 `lost+found`）：启动官方入口，使它完成 initdb 并拉起服务器。`PG_VERSION` 一旦出现，立刻把 `asset-ledger` 写入标记文件并 `sync`，这一写发生在 `pg_isready` 成功之前。包装进程作为 PID 1 把 SIGTERM、SIGINT 转给官方入口的子进程并 `wait`。初始化失败、还没有 `PG_VERSION` 时，沿用官方入口的退出码，不打印「不属于本产品」。
2. 已有 `PG_VERSION`，且标记文件内容合法：`exec` 官方入口，不再写标记。
3. 已有 `PG_VERSION`，但没有标记文件，或内容不合法：向 stderr 写「卷 delivery_ledger_pgdata 不属于本产品，拒绝挂载」，退出码非 0。不调用官方入口，不启动 postgres，不修改数据目录里已有的文件，不删除卷。

因此：直接 `compose up`、卷标签被改成 `asset-ledger` 但数据仍是别人的、对方容器删除后留下的已初始化目录，本产品的 postgres 都不会打开那份数据目录。首次由本产品初始化的卷，升级后标记仍在。`restore.sh` 不得删除这个文件。

### 2.4 环境文件

`deploy/lib.sh` 的 `write_env` 只在首次安装时调用。升级不得覆盖已有 `.env`。

```bash
write_env() {
  dest=$1
  pass=$(od -An -N16 -tx1 /dev/urandom | tr -d ' \n')
  cat > "$dest/.env" <<EOF
DATABASE_URL=postgresql+psycopg://asset_ledger:${pass}@postgres:5432/asset_ledger
POSTGRES_USER=asset_ledger
POSTGRES_PASSWORD=${pass}
POSTGRES_DB=asset_ledger
APP_PORT=8010
PRODUCT_CODE=asset-ledger
TZ=Asia/Shanghai
EOF
  chmod 600 "$dest/.env"
}
```

仓库里的 `.env.example` 使用同一组键，密码和连接串中的口令写成 `PASSWORD`。`start_stack` 在调用 compose 之前执行 `export APP_VERSION=$(读安装目录的 VERSION)`。compose 里 `APP_VERSION: ${APP_VERSION:-0.1.0}` 写在 `environment` 下，从而覆盖 `.env` 里可能残留的旧版本号。镜像标签使用这次导出的版本。

### 2.5 备份与恢复

`backup.sh` 在本产品的 postgres 已经健康时执行。它不连接、不停止客户交付台账的容器。备份目录是 `backups/<YYYYMMDDHHMMSS>/`，其中有 `db.sql` 和当时的 `VERSION`。`db.sql` 来自：

```bash
compose exec -T postgres pg_dump -U "$POSTGRES_USER" -d asset_ledger --no-owner --no-acl
```

本版没有附件，备份不含 `files.tar.gz`。

`restore.sh` 的参数是安装目录和某一次备份目录。备份里缺少 `db.sql` 或 `VERSION` 时退出。先调用 `assert_volume_exclusive`。本产品的 postgres 必须已经健康。不停止对方容器，不执行 `down -v`。

恢复只处理数据库 `asset_ledger`：断开该库上的其它会话，`DROP DATABASE asset_ledger`，再 `CREATE DATABASE asset_ledger OWNER asset_ledger`，然后把 `db.sql` 灌入。不删除 `postgres` 库，不删除名为 `ledger` 的库；若集群里已经有 `ledger` 或任一库有 `public.deliveries`，按第 2.2 节的冲突句退出，且不执行 DROP。不删除 `asset_ledger.owner`。不删除其它备份目录。

## 3. 对象关系

```text
空间（机房 / 机柜 / 仓库 / 办公区 / 柜子 / 工位）
  └── 子空间（按第 4 节矩阵）
资产
  ├── 放在一个空间上（服务器、交换机、防火墙、硬盘）
  └── 或挂在一台服务器上（仅硬盘）
```

每条资产恰好有一个宿主：要么有空间外键，要么有挂载资产外键。硬盘挂在服务器上时不记空间外键。它的空间路径等于那台服务器当前的空间路径。

## 4. 空间

| 内部码 | 页面用词 |
| --- | --- |
| `room` | 机房 |
| `rack` | 机柜 |
| `warehouse` | 仓库 |
| `office` | 办公区 |
| `cabinet` | 柜子 |
| `desk` | 工位 |

### 4.1 父子关系

行是子类型，列是父级。空父级是根。「可」表示允许创建和移入，其余组合拒绝。

| 子类型 | 根 | 机房 | 机柜 | 仓库 | 办公区 | 柜子 | 工位 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 机房 | 可 |  |  |  |  |  |  |
| 机柜 |  | 可 |  |  |  |  |  |
| 仓库 | 可 |  |  |  |  |  |  |
| 办公区 | 可 |  |  |  | 可 |  |  |
| 柜子 |  |  |  | 可 | 可 |  |  |
| 工位 |  |  |  |  | 可 |  |  |

机房的子空间只有机柜。机房内的备件放在仓库节点，或放在仓库下的柜子。在机房下创建柜子时提示「这里不能放柜子」，不产生记录。

拒绝提示用子类型的页面用词：「这里不能放机房」「这里不能放机柜」「这里不能放仓库」「这里不能放办公区」「这里不能放柜子」「这里不能放工位」。

名称必填。去掉首尾空白后长度为 1–100，且不含 `/` 或 `\`。同一父级下，名称忽略大小写后唯一，重复时提示「同级已有这个名称」。不同父级可以同名。根与根也按同级比较。说明可空，最长 2000。

提示：名称为空「请填写名称」；名称过长「名称过长」；含 `/` 或 `\`「名称不能含斜杠」；说明过长「说明过长」。

编辑时表单可以再次提交类型。提交类型与库中类型相同，则继续保存名称、父级、说明和机柜高度。提交类型与库中类型不同，提示「类型创建后不能改」，类型、父级和名称都保持原值。

### 4.2 层数

层数从根算到该节点，包含自身，最多 4。

创建时，新节点层数是父节点层数加 1；父级为空则新节点层数是 1。超过 4 则提示「空间层级过深」，不产生节点。

移动时，该节点的新层数，以及它每一个子孙的新层数，都要小于或等于 4。子孙的新层数等于该节点的新层数，加上子孙相对该节点的距离。有任一节点会超过 4，则提示「空间层级过深」，父级保持移动前的值，子孙关系不变。

因此路径「办公区 / 办公区 / 办公区 / 工位」可以保存。连续四层办公区可以保存。把「办公A / 办公B / 办公C / 工位D」整棵移到另一间根办公区下面时，工位会变成第 5 层，整次拒绝。把子树移到自己的祖先下面，矩阵和层数都允许时保存。把层数为 4 的办公区的父级改为空，该节点成为根，层数变为 1，保存成功。

父级必须存在。父级编号没有对应空间时提示「位置不存在」，父级不变。新父级是自己，或是自己的子孙时，提示「不能放到自己的下级」，父级不变。

移动成功之前，还要检查该空间及子孙上已有资产在新位置下仍满足第 5 节。不满足则提示「移动后已有资产不能留在这里」，父级不变。把放着服务器的仓库柜子移到办公区下，属于这一句。只放着硬盘的办公柜子移到仓库下，硬盘在仓库柜子里仍然合法，移动保存成功。

### 4.3 机柜高度、删除

只有机柜有高度，取值是 1 到 52 的整数，含两端。新建表单预填 42，保存以提交值为准。缺高度时提示「请填写机柜高度」。超出范围、不是整数时提示「机柜高度无效」。其它类型的高度必须为空。提交了高度时提示「这里不使用机柜高度」，不写入。

把机柜高度改到小于本机柜已有设备最高占用 U 时拒绝，提示「机柜高度小于已占用 U 位」，高度保持原值。已有设备的最高 U 在缩小之前按第 5.2 节的闭区间计算。

删除须带确认值 `yes`。不是 `yes` 时提示「请确认删除」，空间还在。存在子空间时提示「下面还有空间」。存在直接放在本空间上的资产时提示「这里还有资产」。挂在服务器上的硬盘不是机柜的直接资产；机柜上还有那台服务器时，删除机柜仍提示「这里还有资产」。

数据库 RESTRICT 触发时，按仍存在的子空间、直接资产返回上面两句，HTTP 400，不返回 500。

### 4.4 空间保存时的提示顺序

一次保存只返回第一句：

1. 名称、说明的必填、长度和斜杠。
2. 类型不属于第 4 节的六种：「类型无效」。
3. 编辑时类型与库中不同：「类型创建后不能改」。
4. 机柜的高度格式；非机柜却带了高度。
5. 父子矩阵。
6. 父级是自己或子孙。
7. 该节点及全部子孙的新层数。
8. 移动后已有资产是否仍能留在新位置。
9. 同级名称唯一。

把机房的父级设成它下面的机柜时，矩阵先返回「这里不能放机房」。把办公区的父级设成自己时，矩阵允许办公区挂在办公区下，随后返回「不能放到自己的下级」。类型不是六种之一时，先返回「类型无效」，不返回「这里不能放…」。

## 5. 资产与位置

| 内部码 | 页面用词 |
| --- | --- |
| `server` | 服务器 |
| `switch` | 交换机 |
| `firewall` | 防火墙 |
| `disk` | 硬盘 |

### 5.1 宿主

空间外键与挂载资产外键恰好一个有值。

- 两个都有值：提示「请只选择一种位置」，不写库。
- 两个都为空：提示「请选择位置」。
- 所指数编号不存在：提示「位置不存在」。

只有硬盘可以把挂载资产外键指向一台服务器。目标不是服务器时提示「挂载目标不是服务器」。

允许的组合：

| 资产 | 机柜，占连续 U | 仓库节点 | 柜子，且根空间是仓库 | 柜子，且根空间是办公区 | 办公区 | 工位 | 服务器 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 服务器 | 可 | 可 | 可 |  |  |  |  |
| 交换机 | 可 | 可 | 可 |  |  |  |  |
| 防火墙 | 可 | 可 | 可 |  |  |  |  |
| 硬盘 |  | 可 | 可 | 可 | 可 | 可 | 可 |

根空间是沿父级向上、父级为空的那个空间。机房节点不能直接放置资产。仓库下的柜子可以放置服务器、交换机、防火墙和硬盘，不使用 U。办公区下的柜子只放置硬盘。

不允许的组合提示「服务器不能放在这里」「交换机不能放在这里」「防火墙不能放在这里」或「硬盘不能放在这里」。硬盘放在机房节点上时用「硬盘不能放在这里」。

还没有任何一种合法空间可供当前类型选择时，表单提示「请先创建可以放置这种设备的空间」。

本资产上仍挂着硬盘，且新类型不是服务器：提示「请先移出硬盘」，类型和宿主都不变。硬盘改成服务器、交换机或防火墙时，若挂载资产外键仍有值，按新类型提示「服务器不能放在这里」「交换机不能放在这里」或「防火墙不能放在这里」，类型和宿主都不变。

### 5.2 U 位

U 位只用于放在机柜上的服务器、交换机和防火墙。

宿主不是机柜时，起始 U 或占用高度只要有一个提交了非空值，就提示「这里不使用 U 位」，不计算这段区间是否超出机柜。只提交占用高度、不提交起始 U，也是这一句。

宿主是机柜时：

- 起始 U 为空：提示「请填写起始 U」。
- 占用高度为空：提示「请填写占用高度」。
- 起始 U 不是整数：提示「起始 U 无效」。
- 占用高度不是大于或等于 1 的整数（含 0、负数、小数）：提示「占用高度无效」。
- 起始 U 与占用高度都是合法整数，但闭区间没有整个落在 1 到该机柜高度之间（含起始 U 为 0）：提示「U 位超出机柜」。
- 闭区间与同一机柜上另一条资产的闭区间相交（含只在端点相接）：提示「U 位重叠」，已有资产的 U 不变。

闭区间是从起始 U 到「起始 U + 占用高度 - 1」，两端都占用。`[1,2]` 与 `[3,4]` 不相交，可以同时保存。`[1,2]` 与 `[2,2]` 相交，拒绝后一条。

新建表单预填占用高度：服务器为 2，交换机和防火墙为 1。该值随表单提交则写入。提交值为空时按上一列提示拒绝。服务端收到空值时，不改写成 2 或 1。

检查重叠的事务按这个顺序做完再提交：`SELECT id FROM spaces WHERE id = :机柜 FOR UPDATE`；然后 `SELECT id FROM assets WHERE location_space_id = :机柜 ORDER BY id FOR UPDATE`；排除正在保存的这一条自身；判断相交；然后写入。资产行不按 `id` 排序就加锁会造成死锁。两个并行请求写入同一机柜的同一 U 时，只有一条成功，另一条提示「U 位重叠」。先后各发一次不算这条并发。

本版按机柜正面的整宽 U 记录。同一 U 上只放一条资产。

### 5.3 硬盘与服务器

硬盘的 BMC IP、业务 IP 和 MAC 保存为空。页面在这三项上对硬盘不作为可填的网络身份；若提交了非空值，按第 6 节拒绝。

硬盘挂在服务器上时，位置备注可写槽位。槽位不参与唯一性，两块硬盘可以写同一个槽位。

删除仍挂有硬盘的服务器时提示「请先移出硬盘」，服务器和硬盘都还在。先把这些硬盘改挂到仓库或其它允许的空间，再删除服务器，则服务器删除成功，硬盘留在新位置。删除硬盘成功时，它所挂的服务器还在。

服务器改到另一个允许的宿主之后，这些硬盘的挂载目标不变。导出中硬盘的空间路径改为服务器的新路径。

数据库 RESTRICT 在删除服务器时若因仍有硬盘而失败，返回「请先移出硬盘」，HTTP 400，不返回 500。

### 5.4 资产保存时的提示顺序

一次保存只返回第一句：

1. 第 6 节的必填、长度和空白。
2. 类型不属于第 5 节的四种：「类型无效」。
3. IP、MAC 的格式。
4. 硬盘上的 BMC IP、业务 IP、MAC。
5. 两个宿主外键都有值，或都为空，或目标不存在。
6. 本资产仍挂着硬盘，且新类型不是服务器。
7. 宿主类型是否允许，含挂载目标不是服务器，以及改类型后旧宿主不再合法。
8. 宿主不是机柜却带了 U。
9. 机柜上的 U 格式、区间和重叠。
10. 资产编号、序列号的唯一性。

## 6. 字段与唯一性

表单里的每个文本字段先去掉首尾空白。去掉之后长度为 0，视为未填。这包括起始 U、占用高度、机柜高度、BMC IP、业务 IP、MAC、型号、位置备注、备注和空间说明。只含空格的占用高度是未填，提示「请填写占用高度」，不提示「占用高度无效」。

| 字段 | 要求 |
| --- | --- |
| 资产编号 | 必填。去掉首尾空白后 1–64 字，中间不能有空白。忽略大小写后在全部资产中唯一 |
| 序列号 | 必填。去掉首尾空白后 1–128 字，中间不能有空白。忽略大小写后在全部资产中唯一 |
| 名称 | 必填。去掉首尾空白后 1–200 字 |
| 类型 | 第 5 节四种之一 |
| 型号 | 可空，最长 200。自由文本，不是型号库 |
| BMC IP | 可空。有值时为点分十进制 IPv4，四段都是 0–255 的十进制整数，不带前导零。硬盘必须为空 |
| 业务 IP | 与 BMC IP 相同。可以与另一条资产相同 |
| MAC | 可空。输入可以是冒号分隔、连字符分隔或 12 位连续十六进制。保存并显示为小写冒号形式，共 17 个字符。硬盘必须为空。可以与另一条资产相同。页面在该字段旁写「本版只记录一块 MAC」 |
| 位置备注 | 可空，最长 200 |
| 备注 | 可空，最长 4000 |
| 登记时间 | 创建时写入，以后修改不改变。时区 `Asia/Shanghai` |

库中保存去掉首尾空白后的原文大小写。唯一索引建在小写形式上。并发冲突与普通重复使用同一提示。资产编号和序列号互不替代：一条的编号可以与另一条的序列号文本相同。

提示：

- 资产编号为空：「请填写资产编号」
- 序列号为空：「请填写序列号」
- 资产名称为空：「请填写名称」
- 资产编号过长：「资产编号过长」
- 序列号过长：「序列号过长」
- 名称过长：「名称过长」
- 型号过长：「型号过长」
- 位置备注过长：「位置备注过长」
- 备注过长：「备注过长」
- 资产编号中间有空白：「资产编号不能有空格」
- 序列号中间有空白：「序列号不能有空格」
- 资产编号重复：「资产编号已存在」
- 序列号重复：「序列号已存在」
- 同级空间重名，含唯一索引冲突：「同级已有这个名称」
- IP 不合法：「IP 格式不正确」
- MAC 不合法：「MAC 格式不正确」

硬盘若填写了网络字段，按 BMC IP、业务 IP、MAC 的顺序只提示第一个：「硬盘不记录 BMC」「硬盘不记录业务 IP」「硬盘不记录 MAC」。

唯一约束冲突时返回上表里的对应句子，HTTP 400，不返回 500。两个并发请求把同名根机房写进去时，一条成功，另一条是「同级已有这个名称」。

## 7. 页面

导航是首页、空间、资产。没有登录表单。

首页显示空间数、资产数、硬盘数，以及最近创建的 20 条资产。硬盘数是类型为硬盘的资产条数，包含挂在服务器上的硬盘。每条链到该资产。

空间列表按父子缩进显示全部空间。空库时说明先建立机房、仓库或办公区，工位要建在办公区下。新建根空间时，类型只有机房、仓库、办公区。空间详情显示从根开始的路径、类型、说明、子空间和本范围资产。添加子空间时，类型下拉只含第 4.1 节允许的子类型。机柜详情显示高度，以及从高 U 到 1 的只读占用表；跨 U 的设备在每一行显示同一资产编号和名称。空 U 只显示 U 号。上架在资产表单里保存。

资产列表显示资产编号、序列号、名称、类型、位置、BMC IP、业务 IP、MAC。位置是空间路径；挂在服务器上的硬盘显示「服务器 」加那台服务器的资产编号。筛选有类型、空间和关键字，三者同时生效。关键字忽略大小写，匹配资产编号、序列号、名称和型号。空间筛选包含该空间的子孙，以及挂在这些空间中的服务器上的硬盘。列表每页 200 条。

资产新建和编辑使用同一组字段和同一套校验。保存失败时已提交的内容留在表单中，原记录不变。

空间或资产的页面不存在时返回 404。空间的文案是「没有这个空间」，资产是「没有这个资产」。

路由：

- `GET /` 首页
- `GET /healthz` 见第 2.2 节
- `GET /spaces`、`POST /spaces` 空间列表和创建
- `GET /spaces/{id}`、`POST /spaces/{id}` 空间详情和修改
- `POST /spaces/{id}/delete` 删除空间
- `GET /spaces/{id}/export.xlsx` 导出该空间范围
- `GET /assets`、`GET /assets/new`、`POST /assets` 资产列表、新建表单和创建
- `GET /assets/{id}`、`POST /assets/{id}` 资产详情和修改
- `POST /assets/{id}/delete` 删除资产
- `GET /assets/export.xlsx` 按列表筛选导出

`/assets/new`、`/assets/export.xlsx` 优先于按编号取出资产的路由。

## 8. Excel

资产列表和空间详情可以导出当前范围。页面没有上传 Excel 的入口。

文件只有一个工作表，表名「资产」。第 1 行依次为：

资产编号、序列号、名称、类型、型号、宿主种类、空间路径、起始U、占用U、挂载于资产编号、BMC IP、业务 IP、MAC、位置备注、备注、登记时间。

类型使用第 5 节的页面用词。宿主种类使用：机柜、仓库、柜子、办公区、工位、服务器。

空间路径从根到该空间，名称之间用 ` / ` 连接。硬盘挂在服务器上时，空间路径等于服务器的空间路径，宿主种类为「服务器」，挂载于资产编号为服务器的资产编号，起始 U 与占用高度为空。

起始 U 和占用高度在有值时写成整数，没有时单元格为空。其它空字段也是空单元格。登记时间的格式是 `YYYY-MM-DD HH:MM`，时区是 `Asia/Shanghai`。

行序按资产编号忽略大小写的字典序，再按资产编号原文。

列表导出服从第 7 节的筛选，包含全部命中行，不受 200 条分页限制。没有任何筛选时，下载文件名是 `资产台账.xlsx`。有筛选时文件名是 `资产台账-筛选.xlsx`。

空间详情导出的范围，等于资产列表以该空间为筛选条件的范围。`filename*` 使用「资产台账-」加上空间名称。名称里的 `` <>:"/\|?* `` 以及 ASCII 控制字符（U+0000 至 U+001F）替换为下划线。`filename*` 按 RFC 5987 做 UTF-8 百分号编码。

响应头同时给出 ASCII 兜底名和 UTF-8 名：

```text
Content-Disposition: attachment; filename="asset-ledger.xlsx"; filename*=UTF-8''%E8%B5%84%E4%BA%A7%E5%8F%B0%E8%B4%A6.xlsx
```

有筛选时，`filename` 为 `asset-ledger-filter.xlsx`，`filename*` 是 `资产台账-筛选.xlsx` 的 UTF-8 百分号编码。空间导出的 `filename` 为 `asset-ledger-space.xlsx`，`filename*` 是上一节的中文文件名。

从一间机房导出时，包含这间机房中各机柜上的设备，以及挂在这些设备上的硬盘，不包含只放在其它仓库的硬盘。

## 9. 验收

1. 在根上创建机房、仓库、办公区可以保存。在根上创建机柜、柜子、工位时分别提示「这里不能放机柜」「这里不能放柜子」「这里不能放工位」，数据库里没有这三条。
2. 机房下可以创建机柜。机房下创建柜子时提示「这里不能放柜子」，该机房下没有柜子。机房下创建仓库、办公区、工位或第二间机房时拒绝。机柜、柜子、工位下创建任何空间都拒绝。
3. 仓库下可以创建柜子。仓库下创建机柜、机房、仓库、办公区或工位时拒绝。办公区下可以创建办公区、柜子和工位。
4. 连续三层办公区，最底层下的工位可以保存，层数为 4。连续四层办公区可以保存。层数已经是 4 的办公区下再创建工位时提示「空间层级过深」，节点数不变。层数为 3 的办公区下可以创建柜子；该柜子下再创建空间时提示「这里不能放」加所提交的类型，而不是「空间层级过深」。
5. 同一父级下把名称改成与同级现有名称仅大小写不同的值时，提示「同级已有这个名称」，原名称还在。两个机房下的机柜可以使用同一个名称。名称含 `/` 或 `\` 时提示「名称不能含斜杠」。两个根机房的名称仅大小写不同时拒绝。
6. 编辑空间时再次提交与库中相同的类型，并改名称，名称变为新值。提交另一种类型时提示「类型创建后不能改」，类型和名称都不变。
7. 把机柜的父级改为空时提示「这里不能放机柜」，父级仍是原来的机房。把子办公区的父级改为空，该办公区成为根并保存成功。
8. 把空间的父级设为自己时提示「不能放到自己的下级」，父级不变。把机房的父级设成它下面的机柜时提示「这里不能放机房」，父级不变。
9. 已有「办公A / 办公B / 办公C / 工位D」，另有根办公E。把办公A 的父级改为办公E 时提示「空间层级过深」，办公A 的父级仍为空，工位D 的路径不变。
10. 把仍放着服务器的仓库柜子移到办公区下时提示「移动后已有资产不能留在这里」，父级仍是仓库。给仓库提交机柜高度时提示「这里不使用机柜高度」，仓库的高度仍为空。
11. 删除仍有子空间的空间时提示「下面还有空间」。删除仍有直接资产的空间时提示「这里还有资产」。机柜上有服务器、该服务器上有硬盘时，删除机柜仍提示「这里还有资产」。确认值不是 `yes` 时提示「请确认删除」。这四种情况下原空间还在。直接造成外键拒绝的删除返回上述中文，状态码不是 500。
12. 服务器、交换机、防火墙可以保存在机柜的合法 U 上，可以保存在仓库节点上，也可以保存在根为仓库的柜子里。后一种的起始 U 和占用高度为空，三条都能保存，同一柜子还可以再保存一块硬盘。保存到办公区、工位、根为办公区的柜子或机房节点时拒绝，提示分别为「服务器不能放在这里」「交换机不能放在这里」「防火墙不能放在这里」，不产生资产。
13. 硬盘可以挂到一台服务器上，也可以放在仓库、柜子、办公区、工位。放在机柜上或机房节点上时提示「硬盘不能放在这里」。挂载目标是交换机、防火墙或另一块硬盘时提示「挂载目标不是服务器」。
14. 同一请求里空间外键和挂载资产外键都有值时，提示「请只选择一种位置」，不产生资产，已有行不变。两个都空时提示「请选择位置」。
15. 同一机柜中起始 U 为 1、占用高度为 2 的设备，与起始 U 为 3、占用高度为 2 的设备，都可以保存。把后者改为起始 U 为 2、占用高度为 2 时提示「U 位重叠」，原 U 不变。起始 U 为 2、占用高度为 1 的设备与已占用 `[1,2]` 的设备也不能同时存在。
16. 仓库中的服务器只提交占用高度、不提交起始 U 时，提示「这里不使用 U 位」，页面正文里没有「U 位超出机柜」。
17. 占用高度为 0 或 1.5 时提示「占用高度无效」。占用高度只含空格时提示「请填写占用高度」，不提示「占用高度无效」。机柜上的起始 U 为 0 时提示「U 位超出机柜」。缺起始 U 时提示「请填写起始 U」。缺占用高度时提示「请填写占用高度」。新建服务器不修改预填值直接提交，占用高度保存为 2。
18. 已有设备占用到第 12U 时，把机柜高度改为 10，提示「机柜高度小于已占用 U 位」，高度仍是原值。高度为 0 或 53 时提示「机柜高度无效」。
19. 资产编号为空白时提示「请填写资产编号」。序列号为空白时提示「请填写序列号」。已有编号 `Ab` 时再保存 `ab`，提示「资产编号已存在」。序列号同样忽略大小写。中间含空格时分别提示「资产编号不能有空格」「序列号不能有空格」。名称只含空白时提示「请填写名称」。
20. 业务 IP 为 `192.168.001.1` 或 `bmc` 时提示「IP 格式不正确」。MAC 输入 `AABBCCDDEEFF` 后，页面和导出都是 `aa:bb:cc:dd:ee:ff`。硬盘填写 BMC IP 时提示「硬盘不记录 BMC」，不产生该硬盘。两台服务器保存同一个业务 IP 时两条都在。资产表单的 MAC 字段旁有「本版只记录一块 MAC」。
21. 服务器仍在机柜上时把类型改成硬盘，提示「硬盘不能放在这里」，类型仍是服务器。服务器上还有硬盘时把类型改成交换机，提示「请先移出硬盘」，类型仍是服务器。硬盘仍挂在服务器上时把类型改成服务器，提示「服务器不能放在这里」，类型仍是硬盘。
22. 服务器上还有硬盘时删除服务器，提示「请先移出硬盘」，两条都还在，状态码不是 500。把该硬盘改放到仓库后再删除服务器，服务器消失，硬盘仍在仓库。单独删除硬盘后，服务器还在。把服务器改到另一机柜的空闲 U 后，硬盘的挂载目标仍是它，导出里该硬盘的空间路径是新机柜的路径。
23. 无筛选导出的工作表名为「资产」，第 1 行 16 列与第 8 节一致，文件名为 `资产台账.xlsx`。响应头含 `filename="asset-ledger.xlsx"` 和 `filename*=UTF-8''%E8%B5%84%E4%BA%A7%E5%8F%B0%E8%B4%A6.xlsx`。类型筛选为硬盘时，数据行的类型都是「硬盘」，`filename*` 对应 `资产台账-筛选.xlsx`。从某机房导出时，含该机房机柜内的设备及其硬盘，不含只放在其它仓库的硬盘。空间名称含 `:` 时，导出的 `filename*` 里该字符变成下划线。
24. 首页、空间页和资产页都没有登录表单。首页硬盘数等于类型为硬盘的条数，含挂在服务器上的。数据库可连接且启动检查已通过时，`GET /healthz` 返回 200，正文去掉空白后是 `ok`。
25. compose 里卷的 `name` 是 `delivery_ledger_pgdata`，项目名是 `asset-ledger`，应用镜像是 `asset-ledger`，库名是 `asset_ledger`。`postgres` 的入口是 `pg-guard.sh`，`command` 是 `["postgres"]`，服务没有 `ports`。两个服务都是 `pull_policy: never`。
26. 本机已有镜像仓库名为 `delivery-ledger` 的容器（含已退出），或卷 `delivery_ledger_pgdata` 的项目标签不是 `asset-ledger` 时，`install.sh`、`upgrade.sh`、`up.sh` 都以非 0 退出，不执行 compose up，不删除该卷，本产品的 postgres 容器不在运行。已装客户交付台账时，其库中 `deliveries` 的行数和抽样列值与这次尝试前相同。
27. `docker volume create delivery_ledger_pgdata` 之后（没有项目标签），`install.sh` 以非 0 退出，日志含「卷 delivery_ledger_pgdata 不属于本产品，拒绝挂载」，postgres 未启动。
28. 干净环境安装成功后，该卷的 `com.docker.compose.project` 是 `asset-ledger`，数据目录中有 `asset_ledger.owner`，去掉末尾一个换行后的内容是 `asset-ledger`。
29. 把一份已有 `PG_VERSION`、没有 `asset_ledger.owner` 的数据目录交给本产品的 compose 时，postgres 容器退出，日志含「不属于本产品」，官方入口没有启动，库中没有新建的 `spaces` 或 `assets`。
30. `COMPOSE_PROJECT_NAME=other` 时执行 `up.sh`，以非 0 退出，日志含「COMPOSE_PROJECT_NAME 必须是 asset-ledger」，不 up。
31. `PRODUCT_CODE` 不是 `asset-ledger` 时应用退出，日志含「PRODUCT_CODE 必须是 asset-ledger」，不创建 `assets`。维护库能列出名为 `ledger` 的数据库，或任一数据库经单独连接后 `to_regclass('public.deliveries') IS NOT NULL` 为真时，日志含「数据库卷与客户交付台账冲突」，不创建 `assets`，不写 `schema_migration`。只在 `asset_ledger` 里找不到 `deliveries`，不能使这次启动继续建表。`docker compose logs app` 能读到上述原句。
32. 两个并行的 HTTP POST 把两台服务器写入同一机柜的同一 U，恰有一条成功，另一条提示「U 位重叠」，该 U 上只有一条资产。先后各保存一次不算满足本条。
33. 两个并发请求创建同名根机房，一条成功，另一条 HTTP 400，正文是「同级已有这个名称」，不是 500。
34. 创建空间时类型写成 `printer`，提示「类型无效」，正文里没有「这里不能放」。创建资产时类型写成 `laptop`，提示「类型无效」，并且不先出现宿主那一句。
35. 已有「办公A / 办公B / 办公C」，把办公C 的父级改为办公A，保存成功，办公C 的层数小于或等于 4。把层数为 4 的办公区父级改为空，该办公区成为根。办公区下的柜子里只有硬盘时，把该柜子的父级改为仓库，保存成功，硬盘仍在这个柜子里。
36. 升级完成后，升级前已有的空间名称和资产编号仍在，`.env` 里的数据库密码不变，`asset_ledger.owner` 仍在且内容不变。

本版验收不包含「本产品安装之后再安装客户交付台账，对方会自动失败」。该顺序写在《部署说明》的红线里，由现场遵守。

## 10. 后续迭代

以后的版本可以在本节增加能力。增加表或列时，在 `migrate.py` 末尾追加结构版本，已有空间和资产的编号、序列号、名称和位置保持原值。

后续迭代包括：登录和权限；自动发现；端口、网线和光纤；机柜拖拽、背面和半 U；厂商型号库；PDU 监控；Excel 导入；办公终端等新的资产类型；货架或库区；尚未指定位置的资产；报废、维修和借出；变更流水；BMC MAC 与业务 MAC 分列；IPv6；附件。
