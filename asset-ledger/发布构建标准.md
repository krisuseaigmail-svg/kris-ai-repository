# 机房/办公资产录入台账 — 发布与升级构建标准

本文固化打包、升级和数据保留。现场步骤见《部署说明》。业务行为、卷预检函数、postgres 包装和验收见《功能说明》。

## 1. 目标运行环境

| 项 | 标准 |
| --- | --- |
| 操作系统 | SUSE Linux Enterprise Server 15.6 |
| CPU | x86_64。镜像架构名 `linux/amd64` |
| 运行方式 | Docker 与 Compose。宿主机不安装 Python |
| 外网 | 运行机可以没有 DNS，也不能访问 `registry-1.docker.io` |
| 数据库 | 只使用本产品 compose 内的 `postgres:16`。卷名固定 `delivery_ledger_pgdata`。本产品独占该卷。禁止与客户交付台账同机挂载。不映射宿主机 5432，不使用、不改写宿主机已有的 PostgreSQL |
| 入口 | postgres 使用 `deploy/pg-guard.sh`。没有 `asset_ledger.owner` 的已初始化数据目录不得启动 |
| 区分 | 镜像 `asset-ledger:<版本>`，compose 项目名 `asset-ledger`，命令为 `docker compose -p asset-ledger`，库名与账号名 `asset_ledger`，`PRODUCT_CODE=asset-ledger` |

## 2. 离线镜像

### 2.1 发布包

产物路径是 `dist/asset-ledger-<版本>.tar.gz`。包内有：

- `VERSION`，与 `pyproject.toml`、compose 默认 `APP_VERSION` 一致
- `app/`（含 `migrate.py`）
- `pyproject.toml`
- `images/asset-ledger-images-amd64.tar.gz`
- `vendor/wheels/` 中的运行依赖 wheel
- `deploy/lib.sh`、`deploy/pg-guard.sh`、`deploy/package.sh`
- `deploy/install.sh`、`deploy/upgrade.sh`、`deploy/up.sh`、`deploy/backup.sh`、`deploy/restore.sh`
- `Dockerfile`、`docker-compose.yml`、`.env.example`
- `功能说明.md`、`部署说明.md`、`AGENT提示词.md`、本文

包内没有现场 `.env`，没有 `backups/`，没有业务库数据，也没有卷 `delivery_ledger_pgdata` 的内容。本版没有用户附件目录。

`install.sh`、`upgrade.sh`、`up.sh` 只调用 `lib.sh` 里的 `assert_volume_exclusive`，不另写卷检查。

### 2.2 镜像与架构

包内镜像只有：

1. `asset-ledger:<版本>`
2. `postgres:16`

二者都是单架构 `linux/amd64`。`docker image inspect <镜像> --format '{{.Architecture}}'` 为 `amd64`。`docker run --rm --platform linux/amd64 <镜像> uname -m` 为 `x86_64`。

在 Apple Silicon 上，`docker pull --platform linux/amd64` 之后还要压扁：`docker create --platform linux/amd64` 得到容器，再 `docker commit` 成本地标签，然后做上面的两项检查。只 pull、不 commit 的镜像不得打进发布包。禁止把 arm64 内容标成 amd64。

基础镜像的拉取前缀默认是 `docker.m.daocloud.io/library`，可由 `PACKAGE_BASE_MIRROR` 覆盖。打进发布包的标签仍是 `asset-ledger:<版本>` 与 `postgres:16`。应用 Dockerfile 的 `FROM` 是 `python:3.12-slim`。

构建应用镜像使用 `vendor/wheels` 离线安装。Dockerfile 的安装命令只有 `pip install --no-cache-dir --no-index --find-links=/wheels`。目录里没有覆盖依赖的 wheel 时，构建失败，不访问 PyPI。`EXPOSE 8000`。`CMD` 是 `["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]`。

wheel 的取得：

- 带二进制扩展的包使用 `pip download --python-version 312 --platform manylinux2014_x86_64 --implementation cp --abi cp312 --only-binary=:all:`。
- `openpyxl`、`et-xmlfile` 以及其它 `py3-none-any` 包另一次 `pip download` 放进同一个 `vendor/wheels`，这次不使用会滤掉 `py3-none-any` 的 `--platform`。

compose 中 `app`、`postgres` 都设 `pull_policy: never`。`postgres` 的 healthcheck 与《功能说明》第 2 节相同；`app` 依赖 `condition: service_healthy`。安装和升级只 `docker load`，再 `docker compose -p asset-ledger up -d --pull never`。

### 2.3 打包命令

在能访问镜像站的开发机执行 `./deploy/package.sh`。禁止用未压扁的镜像手工 `docker save` 代替该脚本。

### 2.4 发版前核对

- `VERSION` 已递增。降级必须显式 `ALLOW_DOWNGRADE=1`。
- 包内两镜像的 `Architecture` 都是 `amd64`，且 `uname -m` 是 `x86_64`。
- 包内有 `app/` 和 `pyproject.toml`，没有现场 `.env`、`backups/` 和业务数据。
- `migrate.py` 若有变更，只在列表末尾追加。
- compose 的 postgres 没有 `ports`，入口是 `pg-guard.sh`，`command` 是 `["postgres"]`。
- 卷名仍是 `delivery_ledger_pgdata`，项目名是 `asset-ledger`。

## 3. 安装与升级

现场安装：

```bash
sudo /tmp/asset-ledger/deploy/install.sh /opt/asset-ledger
```

目标目录已有 `VERSION` 时，脚本退出，提示「已有安装，请使用 upgrade.sh」，不覆盖该目录。安装调用《功能说明》第 2.4 节的 `write_env`，权限 `600`。

升级：

```bash
sudo /tmp/asset-ledger/deploy/upgrade.sh /opt/asset-ledger
```

升级脚本的顺序：

1. 拒绝静默降级。确需回退时先恢复备份，再用 `ALLOW_DOWNGRADE=1`。
2. 调用 `assert_volume_exclusive`。失败则不 up、不删卷。
3. 按《功能说明》第 2.5 节备份。备份失败则不替换程序。
4. 替换 `app/`、`deploy/`、`images/`、Dockerfile、compose 和规格文档。保留 `.env`、`backups/` 和卷 `delivery_ledger_pgdata`。不删除 `asset_ledger.owner`。
5. `docker load` 后导出 `APP_VERSION`（取自新的 `VERSION`），再 `docker compose -p asset-ledger up -d --pull never`。
6. `/healthz` 返回 `ok` 才算完成。失败时打印备份目录，不执行 `down -v`。

日常启动用 `deploy/up.sh`，同样先做 `assert_volume_exclusive`。

运行机禁止 `docker compose build`、`docker compose pull`、不带脚本的 `docker compose up`，以及 `docker compose down -v`。

## 4. 数据保留

业务数据在卷 `delivery_ledger_pgdata` 的库 `asset_ledger` 中。标记文件 `asset_ledger.owner` 与该卷同在。升级、备份、恢复都不更换卷名，不删除该文件。

客户交付台账不得挂载这个卷。脚本在卷标签不是 `asset-ledger` 时拒绝挂载。已初始化但没有合法标记文件时，`pg-guard.sh` 拒绝启动 postgres，并且不改数据目录里已有的文件。

结构变更只通过 `app/migrate.py` 末尾追加。禁止用清空库作为升级步骤。

pytest 的 `DATABASE_URL` 库名是 `asset_ledger_test`，使用独立 Postgres，不得指向现场卷上的业务库。

升级后至少核对：

1. 升级前的空间和资产仍在，资产编号与序列号不变。
2. `.env` 中的库密码未变。
3. 应用仍使用卷 `delivery_ledger_pgdata`，卷标签仍是 `asset-ledger`。
4. `asset_ledger.owner` 仍在，内容仍是 `asset-ledger`。

任一不满足，停用新版本，用该次升级前的备份恢复，再排查。

## 5. 版本号

发版前修改 `VERSION`。`pyproject.toml` 的版本、compose 里默认 `APP_VERSION` 与它相同。有表结构变更时，在《功能说明》第 2 节的结构版本列表追加同一句说明。
